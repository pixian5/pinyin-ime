## 一、GTK immodule e2e（10/10 ✅）

### 难点
本机没有 GTK3 devel 包（/usr 只读、无法安装）。`pkg-config gtk+-3.0` 不可用，
测试客户端无法用常规方式编译。

### 方案：最小原型垫片 + 直链运行时
1. 新入库 `tools/gtk_compat_headers/`：
   - `gtk/gtk.h`、`gdk/gdkx.h`：只声明测试客户端用到的少量 GTK3 原型
     （`gtk_init`、`gtk_window_new`、`gdk_x11_display_get_xdisplay` 等）。
2. 直接链接系统 GTK3 运行时（无需头文件之外的任何 devel 内容）：

```bash
gcc -O2 -I tools/gtk_compat_headers -o tools/gtk_ime_test_client \
    tools/gtk_ime_test_client.c \
    -l:libgtk-3.so.0 -l:libgdk-3.so.0 -l:libgobject-2.0.so.0 -l:libglib-2.0.so.0
```

### 测试脚本
`scripts/xvfb_desktop_ime_test.sh` 参数化重构（DISPLAY / NB 环境变量），流程：
自建 Xvfb(:87) → 起 DBus → 起 fcitx5（带 pinyinime addon）→ 起 GTK 客户端窗口 →
`tools/keysend_target` XTest 注入按键 → 断言客户端应用内上屏回调。

```bash
HOME=/workspace NB=/workspace/native-build DISPLAY=:87 bash scripts/xvfb_desktop_ime_test.sh
```

### 结果
全拼 / 简拼 / 纠错 / 模糊音 / 中英混输 / 退格 / 翻页 / 候选选择 / 标点上屏：**10/10 通过**。
（脚本内补充了 XKB_CONFIG_ROOT 防御，绕开沙箱 xkeyboard-config 路径差异。）

## 二、Qt immodule e2e（10/10 ✅）

### 难点
mamba-env 里的 Qt（libQt5Core/Gui/Widgets/DBus）**缺 platform 插件**，`QApplication`
无法建窗口（`could not find or load the Qt platform plugin "xcb"`）。

### 方案：conda-forge qt-main 组装运行时覆盖层
1. 选包：`qt-main 5.15.15 h2f19be9_6`（依赖 `icu>=75.1,<76.0a0`，与本机 mamba-env
   的 ICU 75 匹配，避免双 ICU 冲突）。
2. 从包内抽出并组装 `native-build/qt-qpa/`：
   - `lib/`：Qt5Core / Qt5Gui / Qt5Widgets / Qt5DBus / Qt5XcbQpa 等
   - `plugins/platforms/libqxcb.so`
   - 补齐 `libxcb-image.so.0`、`libxcb-render-util.so.0`
3. 客户端环境（测试脚本内已封装）：
   `QT_QPA_PLATFORM_PLUGIN_PATH=$QTQPA/plugins/platforms`、
   `QT_PLUGIN_PATH=$BUNDLE/lib/qt5/plugins`、`QT_IM_MODULE=fcitx`，
   `LD_LIBRARY_PATH` 以 `qt-qpa` 优先。

### 测试脚本

`tools/keysend_target` 注入按键 → 断言输出 `COMMIT:<上屏文本>` 行。


## 三、.deb / .rpm 一键安装包

### 新增/重写文件
| 文件 | 职责 |
|---|---|
| `scripts/build_packages.sh` | 主入口：组装 buildroot → rpm / deb → 内置校验（`all`/`rpm`/`deb`） |
| `scripts/make_deb.py` | 纯 Python 组装 .deb（ar + control.tar.gz + data.tar.gz + md5sums，无 dpkg 依赖） |
| `scripts/setup_rpmtools.sh` | 只读 /usr 沙箱下，从 rpm-build 包解出可用 rpmbuild（含 find-requires/find-provides 适配） |
| `packaging/pinyin-ime.spec` | 重写：`@VERSION@` 占位符由构建脚本替换；LGPL-2.1-or-later |

### 产物与内容
```
dist/pinyin-ime-0.9.103-1.aarch64.rpm    369 KB   （xz 压缩）
dist/pinyin-ime_0.9.103_arm64.deb        566 KB   （gzip 压缩）
```
包内容一致（仅路径布局不同）：
- rpm：`/usr/lib64/fcitx5/libpinyinime.so`；deb：`/usr/lib/aarch64-linux-gnu/fcitx5/`
- addon 描述 `pinyinime.conf` + 配置模板 `pinyinime.conf`（含 14 组独立模糊音开关）
- `/usr/bin/pinyin_ime_cli` + `/usr/share/doc/pinyin-ime/README.md`
- **不含** LM/dict 数据：addon 会自动搜索发行版 libime 标准路径
  （/usr/share/libime、/usr/lib{,64}/libime 等），或 conf 里 `DataDir` 指定；
  deb 声明 `Depends: fcitx5`、`Recommends: libime-data`。

### 沙箱 rpmbuild 适配（两处根因）
1. openEuler 自带 `/usr/bin/rpm` **无构建功能**（`-bb: unknown option`）：必须
   用 rpm-build 包解出的 rpmbuild ELF（`/usr/lib` 只读 → 沙箱内解包到
   `native-build/rpmtools/`）。
2. **依赖生成器静默失效**：openEuler 的 find-requires/find-provides 走
   `/usr/lib/rpm/rpmdeps` 的"内部生成器"，在沙箱（fileattrs 不全）下**输出为空**
   → 打出的包只有手写 Requires，没有 soname 自动依赖。
   修复（见 `scripts/setup_rpmtools.sh`）：
   - `find-requires`/`find-provides` 重写为**逐文件调用 elfdeps** 的包装
     （非 ELF 文件 exit 1 → `2>/dev/null || true` 跳过，等价 openEuler `__deploop` 思路）；
   - rpmbuild 侧加 `--define "_use_internal_dependency_generator 0"` 强制走外部生成器。
   修复后 RPM 依赖 36 条，含：
   `libFcitx5Core.so.7()(64bit)`、`libIMEPinyin.so.0()(64bit)`、
   `libc.so.6(GLIBC_2.34)(64bit)`、`libstdc++.so.6(GLIBCXX_3.4.32)(64bit)` 等。

### 不 strip 决策
打包默认**不 strip、不生成 debuginfo**（`__brp_strip %{nil}` 等，两个构建路径统一），
保证包内二进制与 S3/仓库发布产物**字节一致**，便于 md5 校验：

```
包内 libpinyinime.so  md5 = eb29b7dbc8e5dd37c16acf9a9f5956af（= fcitx5-addon/build 产物）
包内 pinyin_ime_cli   md5 = 048e2f0521710bfe639778e01299cb60（= deploy/bin 产物）
```

### 验证记录
- rpm 假根安装：`rpm --initdb --root=/tmp/rpm-inst-test` + `rpm -i --nodeps --noscripts` → OK，文件列表正确
- deb：ar 成员 = debian-binary/control.tar.gz/data.tar.gz ✓；control 字段完整 ✓；md5sums 5/5 全过 ✓
- 两包解出文件 md5 与构建产物一致（见上）✓
