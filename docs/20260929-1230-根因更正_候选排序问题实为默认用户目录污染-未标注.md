# 根因更正：候选排序「随进程旋转」实为默认用户目录污染（2026-09-29）

> ⚠️ 本文更正 `20260929-1150-addon单音节候选排序随进程随机旋转问题-未标注.md` 的结论：
> 那个「ASLR 旋转」的判断是**错误的**。真实根因是实验时的默认用户数据目录污染，不是 libime/addon 缺陷。

## 真正的根因（一句话）

第 11 轮观测到的「addon 单音节候选排序随进程随机旋转」「addon 分数与 CLI 不同」，全部是由
**`~/.local/share/pinyin-ime/` 里残留的 `user.history` + `user.dict`** 造成的——那是之前用 CLI
**行模式没带 `--user-data`** 探测候选时，误写入默认用户目录的学习历史；随后我在**没有写 conf** 的
情况下启动 addon，它回落到这个被污染的默认目录，从而对单音节候选做了错误重排。

## 决定性证据链（比第 11 轮的排除表更关键的一步）

| 实验 | 结果 |
|---|---|
| addon **不写 conf**（落默认 `~/.local/share/pinyin-ime`，已被污染） | 分数错误压缩、跨进程出现「旋转」 |
| addon **不写 conf** + 清空 `~/.local/share/pinyin-ime` | 分数恢复正常 |
| addon **写 conf**（`UserDataDir=/tmp/...`，隔离）+ 故意保留污染的 `~/.local` | 分数仍正确 → conf 正确覆盖默认目录 |
| 相同条件下 3 次 fresh 重启 | 3/3 完全一致（确定、正确） |

结论：**conf 的 `UserDataDir` 读取与覆盖完全正常，addon 的候选排序本身就是确定的、正确的**。

## 澄清错误的计算

第 11 轮「5 次 fresh 重启得 5 种旋转」的 `pn()` 只 `pkill fcitx5` + `rm -rf /tmp/pinyin-ime-x11-ud`，
**从没写 conf**，因此 addon 一直用的是默认 `~/.local/share/pinyin-ime`（污染源未清）；「旋转」是污染
历史里「以/把/亿…」等近距分数在重新落盘后彼此换位的结果。所谓「ASLR 旋转」是误读。

## 经验教训（写进这行的原因）

- **CLI 行模式 / 任何不带 `--user-data` 的探测，会污染默认用户目录** `~/.local/share/pinyin-ime`，
  进而污染后续 addon 实测。**测试与探测一律显式 `--user-data`**（`test_interactive.py` /
  `smoke_test.sh` 均已隔离，`xvfb_ime_test.sh` 也已用 conf 写 `UserDataDir=/tmp/...` 隔离）。
- 排查「随机/不确定」问题前，**先核对数据是否被隔离**，再归因到算法/并发/ASLR。本轮在第 12 轮
  才补上「默认用户目录」这一环，代价是误判了两轮、并写了一份错误结论的 docs。

## 对后续测试的影响（正面）

- addon 侧单音节翻页选字的确定性断言**可以补回**了（根因是数据污染，非竞态/非 libime 缺陷）。
  下一轮可在 `xvfb_ime_test.sh` 里把「`=` 翻页选字」用例加回（隔离目录下 idx=9 恒为「亿」）。
