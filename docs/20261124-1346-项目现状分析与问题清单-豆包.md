## 2. 问题清单（按严重度）

### P0-1 准确率指标是自证式：语料与预设在同一提交里被同步改写

**证据链**

1. `12585a0 "v0.9.170: 评测准确率 77%→100% 首选命中"`：源码只改了 `pinyin_ime_cli.cpp` 2 行、`quick_input.h` 7 行，却新增 `cpp/eval_corpus.txt` 113 行。
2. `a6fa5ad "189条语料 100%首选命中 + 预设冲突修复"`：同一提交同时
   - 往 `cpp/abbr_presets.h` 新增 29 条单字预设：`{"de","的"}`、`{"le","了"}`、`{"shi","是"}`、`{"da","大"}` …
   - 把 `cpp/eval_corpus.txt` 改写成 `de→的`、`le→了`、`shi→是`、`da→大` …
3. 现状核对：`abbr_presets.h` 共 **398 条**预设，`eval_corpus.txt` 共 **189 条**语料，其中 **54 条（28.6%）的期望答案可以由预设表直接给出**。

也就是说：这批"100%"里至少有近三成是"把答案写进预设、再让评测去读同一张预设表"。

**更深的问题**

- `scripts/run_eval.sh` 的依赖是仓外的 `pinyin-ime-s3/v0.9.139/{lib,share}` 与 `cpp/build/pinyin_ime_cli`，这两个路径都被 `.gitignore` 排除。**换一台机器无法复现这个 100%**。
- 评测口径是 `echo "$input" | CLI | head -1`，单串直出、无上下文、无语料外测试集，和真实打字（连续输入、上下文选词、简拼、混输）不是一回事。
- `bench/eval.py` 规划了一年（详见 2026-11-03 分析 D1），**至今不存在**。

**影响**：任何"准确率提升"的提交都无法判定真伪；继续在这套语料上调，只会让指标更漂亮、产品更不准。

- CLI 与 addon 能力继续分叉：云拼音两端都有，皮肤几乎只在 CLI（19 处 vs addon 1 处）。

38 篇 `docs/*.md`，`文档索引.md` 缺 15 篇；根目录 14 个 md 中 `ANALYSIS.md`、`RESULTS.md`、`PROJECT_STATUS.md`、`PLAN-A.md`、`USABILITY_REPORT.md` 等均未入索引。索引的"必须同步"规则自己没被遵守。

81 个 sh + 43 个 py 中，**59 个**含 `/root/...` 或 `pinyin-ime-s3/...` 硬编码路径，离开原沙箱即不可用。

### P1-10 云拼音只对自建 mock 验证过

`cloud_pinyin.cpp`（350 行）确实发真 HTTP（libcurl + 磁盘缓存 + in-flight 去重），这是实质进步；但：
- 默认关闭，真实服务端协议、鉴权、限流、失败降级都没有对接；
- 实机验证用的是 `scripts/mock_cloud_pinyin_server.py` 本地 mock，"能取到网络词"只在 localhost 成立；
- 每次字母输入都触发一次前缀查询，README 自己写"真实服务上线前建议加 250ms 防抖"——即热路径风险已知未修。

## 3. 三个"看起来在进步、实际在退化"的模式

1. **指标上涨靠改考题**：77%→100% 的两次跃升都伴随语料/预设同改。这是最危险的一条，因为它会让后续所有判断失真。
2. **每版加功能、不加验证**：12 个版本新增皮肤、云拼音、缩写扩展、长句预测，但没有一次用统一口径回归"是否拉低整句准确率"。
3. **发布物与源码脱节**：发布工程停留在 v0.9.121（RPM/DEB/Release），源码已到 0.9.175，中间 54 个版本没有可安装产物与校验链。

---

## 4. 建议（最小可执行，按顺序）

1. **冻结功能一个迭代，先做可信评测**
   - 新增唯一入口 `bench/eval.py`（或 CLI `--bench-json`），只测真实交付物（CLI 交互管线 / addon E2E）。
   - 语料要求：≥1000 句、四域（新闻/百科/口语/日常），**与 `abbr_presets.h`、句式模板、联想库零交集**（自动化查重，命中即剔除）。
   - 产出一份冻结基线 `bench/configs/baseline.json`（版本 + commit + 指标），此后回退 >1.0pp 即 CI 报红。
   - 上线后**把现有 189 条语料降级为"功能自检"，不再对外宣称准确率**。
2. **版本单一来源**：`cmake/version.h.in` + `configure_file`，删掉 CLI 的 `0.9.86` 字面量；`ci_static.sh` 增加"源码中禁止版本字面量""CHANGELOG 必含当前版本""README 只允许一个当前版本标题"。
3. **仓库卫生**：`git rm --cached` 8 个 ELF 并补 `.gitignore`（`cpp/quick_input_test*` 保留 `.cpp`、`tools/*_test`、`pinyin-ime/`）；`ci_static.sh` 增加"禁止提交 ELF/PE"检查。目标 `.git` 回到 4.5MB 以内。
4. **先改结构再改算法**：拆 `quick_input.h`（quick_input / skin / emoji / clipboard / cloud）+ 抽 `core` 静态库，两端共用一条候选管线；否则每个新功能都要写 2~4 份。
5. **补 `LICENSE`**（建议 LGPL-2.1+ 或与 libime 一致），并在 README 写清第三方组件许可。
