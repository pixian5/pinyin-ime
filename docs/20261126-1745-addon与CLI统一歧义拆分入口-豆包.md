# addon 与 CLI 统一歧义拆分入口（v0.9.183）

> 2026-11-26 17:45 · 豆包 · 版本 0.9.182 → 0.9.183

## 1. 背景

v0.9.182 修掉了 CLI 侧「`xianzai` 被拆成 `xi'an'zai`」导致的解码损失，但同一个问题在 fcitx5 addon 里还留着：`pinyinime.cpp` 有两处直接调用 `disambiguate_pinyin`——

- 第 793 行（`Ctrl+Z` 撤回上屏后恢复预编辑）：把整串拼音重新拆分后再 `context_.type()`；
- 第 1729 行（每次字母输入后）：如果拆分结果与当前预编辑不同，就 `ctx.clear()` 重打一遍。

也就是说，GUI 里连续打 `xianzai` 仍可能被拆成 `xi'an'zai`，候选变成「西安在」。更糟的是第 1729 行在**每个键**都做一次「清空 + 重打」，本身也是一笔无谓开销。

## 2. 改动

1. `cpp/abbr_presets.h` 新增统一入口 `disambiguate_if_needed()`（全局内联函数）：
   - 含空格/标点的输入 → 交给 `disambiguate_pinyin`（原有分段逻辑）；
   - 纯字母且 `pinyin_fully_segmentable()` 为真（即完全可由合法音节拼成）→ **原样返回，不拆**；
   - 其余（真简拼、混输、尾部残缺）→ 仍走 `disambiguate_pinyin`。
   同时给 `pinyin_fully_segmentable` 加了前向声明，使该头文件不再依赖 include 顺序。
2. `cpp/pinyin_ime_cli.cpp` 删除 v0.9.182 里那份本地静态实现，改用共享入口；`v11_shortcut_allowed` 保留在 CLI（那是 CLI 的预解码捷径，addon 没有这条路径）。
3. `fcitx5-addon/pinyinime.cpp` 两处调用点（793、1729）改为 `disambiguate_if_needed`。

## 3. 验证

- **准确率不变**：CLI 在 1200 句 holdout 上仍为 **句级 27.83% / 字级 84.81%**（与 v0.9.182 完全一致，说明这次改动只影响 addon 行为）。
- **行为抽查**：`xianzai → 现在`（第二候选为日期时间）、`nianqing → 年轻`、`bjdx → 北京大学`、`time → 17:47:58`。
- **单测**：**721 passed / 0 failed**（新增 5 条 v183 用例：`xianzai/nianqing` 原样保留、`xianyoud` 仍拆分、带空格走原逻辑、空串安全）。
- **构建**：chroot（Ubuntu 24.04 + libime 1.1.5）CLI 编译通过；fcitx5 addon 编译通过（含 `libpinyinime.so`）。
- **未能验证**：addon 的输入行为需要真实 fcitx5 + GUI 才能确认，本轮只有编译级验证（与 v0.9.179 时 addon 的处理方式一致）。

## 4. 遗留

- addon 第 1729 行仍是「每键都重打预编辑」的实现；即便不再误拆，`ctx.clear() + 重打` 在长句下也是白花的时间。后续应改为「只在真正需要拆分时重建，且复用已输入前缀」。
- `full_pinyin_preset_map` 的单音节硬覆盖（`xian→西安`、`ji→鸡`、`yu→鱼`）仍在，属产品取舍。
- 91%/68% 目标仍不可达，路线仍是重排 / 换 LM。
