# Ubuntu 24.04 双架构编译（ARM64 + AMD64，均 64 位）+ v0.9.125 i 模式编译修复

> 时间：2026-10-28 18:16
> 模型：Hy3
> 背景：本机 macOS（Apple Silicon，arm64），无法本地编译 Linux 二进制；用 docker buildx 多架构编译。
> 目标：产出 Ubuntu 24.04 下的 ARM64（aarch64）与 AMD64（x86-64）两套 64 位二进制。

## 一、方案选择

| 方案 | 说明 | 结论 |
| --- | --- | --- |
| 源码编译 libime/fcitx5 | 从源码编 libime 1.1.17 + fcitx5 5.1.23，再编输入法 | amd64 需 QEMU 模拟，耗时数小时，弃用 |
| **Ubuntu 系统包（采用）** | `apt` 装 libime 1.1.5 + fcitx5 5.1.7 的 dev 包，直接编 cpp / fcitx5-addon | 几分钟完成，文档（2026-10-19 Ubuntu 打通）已验证可行 |

源码侧已做 libime 1.1.5 兼容（`pinyin_ime_cli.cpp` 的 L_R/Correction/GB 跳过、M3 纠错兜底；`fcitx5-addon/CMakeLists.txt` 的 `add_fcitx5_addon` 兼容宏），故系统包方案可行且最快。

## 二、新增文件

- `docker/Dockerfile.ubuntu`：基于 `ubuntu:24.04`，多阶段。builder 装 libime/fcitx5 dev 包 + `libime-data`/`libime-data-language-model`，cmake+Ninja 编出 `pinyin_ime_cli`(CLI)、`libime_bench`、`pinyin_corrector_test`、`quick_input_test`、`libpinyinime.so`(addon)、`pinyinime.conf`，收集到 `/out`，export 阶段用 `scratch` 只留 `/out` 供 `--output type=local` 导出。
- `scripts/build_ubuntu_multiarch.sh`：`docker buildx` 分别以 `--platform linux/arm64` 与 `linux/amd64` 构建，导出到 `dist/ubuntu/arm64` 与 `dist/ubuntu/amd64`。arm64 本机原生、amd64 走 QEMU。

`.gitignore` 已追加 `dist/ubuntu/`（编译产物不入库）。

## 三、编译中暴露的两个源码 bug（v0.9.125 引入）

干净 Ubuntu 24.04 构建下，`pinyin_ime_cli` 在 openEuler 上没暴露的 i 模式回归被暴露——说明 v0.9.125 大概率从未真正编译成功过（只写了发布文档）。两个 bug：

1. **`cpp/quick_input.h` 命名空间过早闭合（行 798）**
   - `namespace pinyin_ime {` 在行 28 打开，却在行 798 被 `} // namespace pinyin_ime` 提前关闭。
   - 导致 `is_i_mode` / `i_mode_lookup` / `association_lookup`（行 801–1061，i 模式 + 联想词）掉到**全局命名空间**。
   - `pinyin_ime_cli.cpp` 用 `pinyin_ime::is_i_mode` 限定调用 → 编译报“未声明”。
   - 修复：把命名空间闭合 `}` 移到文件末尾（行 1061）。`quick_input_test.cpp` 用 `using namespace pinyin_ime` 且调用不带前缀，移入命名空间后仍可解析。

2. **`cpp/pinyin_ime_cli.cpp` 联想变量声明晚于使用**
   - `commit` lambda（行 1912，`[&]` 捕获）在行 1929–1930 给 `assocCands` / `assocMode` 赋值，但两者与 `lastCommitted` 直到行 2363–2365 才声明 → 编译报“未声明”。
   - 修复：把 `bool assocMode` / `std::vector<std::string> assocCands` / `std::string lastCommitted` 三行声明提到 `commit` lambda **之前**（行 1908 后），并删除行 2363–2365 的重复声明。

## 四、版本号

源码已修改，按规约 `VERSION` +0.0.1：**0.9.125 → 0.9.126**。
同步更新 `fcitx5-addon/CMakeLists.txt` 的 `project(pinyinime VERSION 0.9.121 ...)` → `0.9.126`（此前与根 VERSION 已漂移）。

> 注：该 CMakeLists 第 29 行 `set(PINYINIME_VERSION ${PROJECT_VERSION})` 会把 addon conf 的 Version 强制覆盖为 `PROJECT_VERSION`；只要 `project(... VERSION ...)` 与根 `VERSION` 同步（现均为 0.9.126），addon 版本即正确。如需让根 `VERSION` 真正成为唯一来源，可后续删除该行，本次未改以免偏离“编译”主业。

## 五、产物与验证

导出目录：`dist/ubuntu/arm64/`、`dist/ubuntu/amd64/`，各含 6 个文件：
`pinyin_ime_cli`、`libime_bench`、`pinyin_corrector_test`、`quick_input_test`、`libpinyinime.so`、`pinyinime.conf`。

### 架构确认（`file`）
- arm64：`pinyin_ime_cli` → `ELF 64-bit LSB pie executable, ARM aarch64` ✅
- amd64：`pinyin_ime_cli` → `ELF 64-bit LSB pie executable, x86-64` ✅

### 运行库冒烟（容器内 `apt install libimepinyin0 libimecore0 libimetable0 libfcitx5utils2 libime-data libime-data-language-model`）
- arm64：`echo "nihao" | ./pinyin_ime_cli --top1 --quiet <LM> <DICT>` → **你好** ✅；`quick_input_test` 119/119 ✅
- amd64：同上 → **你好** ✅；`quick_input_test` 119/119 ✅
- CLI 自动探测到系统 LM/dict：`/usr/lib/<arch>-linux-gnu/libime/zh_CN.lm` 与 `/usr/share/libime/sc.dict`。

> 注意：冒烟容器里运行库包名带版本号（`libimepinyin0` 等），不要写 `libimepinyin`（该名在 Ubuntu 不存在，会静默安装失败、报 `libIMEPinyin.so.0 not found`）。

## 六、目标机部署

1. 拷贝 `dist/ubuntu/<arch>/` 下二进制到目标 Ubuntu 24.04 机器。
2. `sudo apt install libimepinyin0 libimecore0 libimetable0 libfcitx5utils2 libime-data libime-data-language-model`
   （addon 还需 `libfcitx5core0 libfcitx5config0`）。
3. CLI 直接 `echo "nihao" | ./pinyin_ime_cli`（自动找系统 LM/dict）；addon 按 fcitx5 常规方式安装 `libpinyinime.so` + `pinyinime.conf`。
