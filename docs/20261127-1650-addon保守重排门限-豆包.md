# addon 保守重排门限（v0.9.209）

## 问题

v0.9.207 的 4-gram 对 CLI 提升 +1.25pp，但 addon 逐键路径只有 30.17%，低于 v0.9.204 的 30.25%。原因是 4-gram 会把部分原本正确的 libime top1 无条件换掉；addon 的候选池/逐键路径对这类换位更敏感。

## 方案

在字符重排时增加“原分差门限”：

- 计算当前候选的 libime 原始分 `base` 与字符分 `score = base + alpha * charLM(text)`；
- 取所有完整句候选的 `baseTop`；
- 只有 `base >= baseTop - kRerankBaseGate` 的候选才允许参与靠前排序；低于门限的候选保留但降权（`score -= 100`），避免高置信 top1 被 4-gram 无条件换掉；
- `kRerankBaseGate = 1.0f`；
- 短候选（首候选文本 UTF-8 < 18 字节，约 6 个汉字）不套门限，保持原短词规则，避免 `jrsm` 从“加入什么”变成“敬若神明”。

CLI 与 addon 使用同一规则；正常用户路径零额外 I/O。

## 结果

CLI nbest=45 全量 1200 句：Top1 **31.67%**（v0.9.207 31.58%），字级 86.34%。

addon 真实 fcitx5 + Xvfb + GTK3 全量 1200 句：

| 指标 | v0.9.204 trigram | v0.9.207 4gram | v0.9.209 门限 |
|---|---|---|---|
| Top1 | 30.25% | 30.17% | **30.92%** |
| Top5 | 45.17% | 45.92% | 45.17% |
| Top10 | 49.83% | 49.50% | 49.17% |
| MRR | 0.3689 | 0.3707 | 0.3729 |
| 字级 | 86.24% | 86.42% | 86.37% |

分域（v0.9.209）：baike 31.0、news 40.33、recent 33.33、wiki 19.0。相对 v0.9.207，news +1.33pp、recent +2.00pp，wiki -0.67pp；Top1 净增 **+0.75pp**，Top5 略降 0.75pp，属于用更深候选换首屏正确率的取舍。

## 复现与门禁

- 训练模型不变：`data/char_trigram.bin` v2，3,170,231 字节；`ci_build.sh` 的 clean 重训 `cmp` 仍应通过。
- 42 例 CLI 快照：仅版本头变化，`jrsm` 保持“加入什么”。
- 最终复测 addon 30.92% / 86.37%、Top5 45.17%、Top10 49.17%、MRR 0.3729、P50 502.7ms / P95 609.6ms / P99 695.5ms。
- `ci_build.sh` 通过（nbest=10 Top1 31.42% / 86.06%）；`ci_static.sh` 通过；安装矩阵 30/30；三件套 SHA256 校验 OK。

## 风险

- 门限 1.0 是在 CLI 离线扫描 + addon baike 300 上调出的，存在对当前 1200 句 holdout 过拟合的风险；下一轮应在新增 holdout 或跨域数据上复核。
- Top5 下降说明部分正确答案被压到更后面；如果产品更看重翻页率，需要重新评估门限。
