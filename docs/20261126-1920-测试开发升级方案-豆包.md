# 测试开发升级方案（2026-11 版）

> 2026-11-26 · 豆包 · 适用范围 v0.9.191 起

## 1. 现状盘点

已有：

- **单元测试**：`cpp/quick_input_test.cpp`（721 条，纯函数，无 libime 依赖）、`pinyin_corrector_test`、`cloud_pinyin_test`；
- **静态检查**：`scripts/ci_static.sh`（版本单一来源、仓库卫生、打包守卫、文档存在性、`git diff --check`）；
- **准确率评测**：`bench/eval.py` + 1200 句零泄漏 holdout + `scripts/eval_chroot.sh` 一键跑，基线门禁 `bench/baseline.json`；
- **安装验证**：本轮之前全靠人工敲命令（dpkg/rpm/runtime 三条路径各敲一遍）。

缺口（按危害排序）：

1. **安装/升级没有任何自动断言**：靠我手工看输出，换个版本就可能静默坏掉（0.9.189 就出过 `--force-overwrite` 才能装、升级删 `sc.dict` 两个坑）。
2. **CLI 行为没有快照**：721 条单测都在纯函数层，CLI 壳层（消歧、v11 捷径、批量路径）只能靠 holdout 准确率总量兜，掉了 0.1pp 没人知道是哪类输入退化的。
3. **无覆盖率数据**：不知道 7000 行 quick_input 里哪些分支从未被测到。
4. **无内存/未定义行为检查**：ASan/UBSan 从未跑过，长句/异常输入下有没有越界未知。
5. **无模糊测试**：拼音串、简拼、混输、非法字节都可能触发边界问题，目前只靠手写用例。
6. **addon（GUI 层）零自动测试**：`fcitx5-addon/pinyinime.cpp` 1700+ 行只在 chroot 编译过，行为靠人工。
7. **发布前检查靠脑记**：VERSION/CHANGELOG/README/文档索引/基线版本五处一致性靠 `ci_static.sh` 部分覆盖，缺发布专用门禁。
8. **`scripts/` 目录 110+ 个历史脚本**，没有清单，新人无法判断哪个还能用。

## 2. 目标与硬指标

| 指标 | 现状 | 目标 |
| --- | --- | --- |
| 安装矩阵自动断言 | 0 | deb / rpm / runtime 三条路径全部脚本化，一条命令出 PASS/FAIL |
| CLI 行为回归 | 仅总量准确率 | 固定输入快照 ≥40 例，逐条比对 top1 |
| 行覆盖率（quick_input 系） | 未测 | ≥60%，报告入库 `bench/results/coverage/` |
| 内存检查 | 无 | 单测 + 200 句批处理 ASan/UBSan 零报错 |
| 模糊测试 | 无 | 随机/变异输入 10 分钟无 crash、无 UB |
| 发布门禁 | 分散 | `scripts/release_check.sh` 一条命令，失败即拒绝发布 |
| addon 自动测试 | 0 | 至少引擎层候选生成可在无 GUI 下断言 |

## 3. 测试分层（L0–L4）

- **L0 静态**：`ci_static.sh` + 编译警告（`-Wall -Wextra` 清零）+ 版本一致性。
- **L1 单元**：纯函数单测（现有 721 条）+ 新增消歧/快照相关用例；覆盖率门槛。
- **L2 集成（CLI）**：`pinyin_ime_cli --batch` 固定语料快照 + holdout 准确率 + 延迟。
- **L3 安装/升级**：deb/rpm/runtime 安装、卸载、升级、SHA 校验、默认路径解码。
- **L4 运行时（GUI）**：fcitx5 + Xvfb 下真实键入（依赖能装 fcitx5 主程序的环境），以及人工 5 分钟验收清单兜底。

## 4. 分阶段实施

### P0 门禁与安装矩阵（v0.9.191）

1. `scripts/test_install.sh`：chroot 内自动跑
   - `build_packages.sh all`（可 `--skip-build`）
   - `sha256sum -c SHA256SUMS_v$VERSION`
   - deb：`dpkg -i` → 断言 `Status: install ok installed`、`Version`、`pinyin_ime_cli --version` 一致、包内**不含** LM/dict、`Depends` 含 `libime-data`
   - rpm：`rpm -i` → `rpm -q`、文件列表、CLI 冒烟 → `rpm -e` 干净
   - runtime：解压 → `install.sh` → 解码冒烟 → `uninstall.sh` → 断言 CLI/addon 移除、`sc.dict` 保留
   - 输出 PASS/FAIL 矩阵，任一失败退出非 0
2. `scripts/cli_snapshot_test.sh` + `bench/snapshots/cli_top1.tsv`：固定输入逐条比对 top1，差异打印 `input / expected / got`
3. `scripts/release_check.sh`：VERSION ↔ 源码/包配置文件/CHANGELOG/README/文档索引/baseline 六处一致性 + `ci_static.sh` + 单测 + 快照（可选 `--full` 加打包与评测）

验收：`bash scripts/test_install.sh` 全绿；故意改一个快照期望值能让快照测试失败；`release_check.sh` 在版本不一致时拒绝通过。

### P1 覆盖率与内存检查（v0.9.192–193）

- gcov 构建 `quick_input_test` + `pinyin_ime_cli`，`scripts/coverage.sh` 生成行覆盖率摘要（按文件 top 缺失行）；
- `-Wall -Wextra` 编译 CLI/addon，警告清零（新增守卫：编译日志出现 warning 即失败）；
- ASan/UBSan 版本单测 + holdout 前 200 句批处理；
- 覆盖率报告写入 `bench/results/coverage/v<ver>/summary.txt`（不入库，README 记录数字）。

### P2 模糊与压力（v0.9.194–195）

- 简易变异 fuzz（无 libFuzzer 依赖）：对 `disambiguate_pinyin`/`pinyin_fully_segmentable`/简拼启发式喂随机 UTF-8、超长串、混合标点，跑固定时长；
- 压力：10k 字符长句、单字符重复、空输入、纯英文/emoji/数字；
- 断言：不 crash、不越界（配合 ASan）、耗时上限。

### P3 运行时与 GUI（v0.9.196–197）

- 先把 chroot 里装 `fcitx5` 主程序 + Xvfb + GTK 前端（若 apt 缓存/内网源可用）；不可行则写「人工验收清单」并固化输出采集脚本；
- addon 引擎层无 GUI 断言：直接构造 `PinyinimeEngine` 输入串，断言候选列表与 CLI 一致（同一 libime、同一数据）。

### P4 发布与升级（v0.9.198+）

- 升级矩阵：0.9.188→0.9.189→0.9.190→最新 连续升级不断链；
- 回滚演练：降级安装 + `uninstall.sh`；
- CI：GitCode runner 无 libime 开发包，改为「本地 runner 脚本 + 预构建镜像」或在 CI 里用 chroot 镜像（可行后接入）。

## 5. 每次发版的固定流程

1. 改代码 → `VERSION` +0.0.1；
2. `bash scripts/ci_static.sh`；
3. 单测（`quick_input_test` 721+）；
4. `bash scripts/cli_snapshot_test.sh`；
5. `bash scripts/test_install.sh`；
6. `bash scripts/release_check.sh`；
7. 准确率：`bash scripts/eval_chroot.sh`（不低于基线）；
8. commit + push（Mac 环境）。

## 6. 非目标

- 不追求 GUI 像素级自动化（成本高、环境脆弱），以引擎层断言 + 人工清单替代；
- 不引入重型测试框架（GoogleTest/Catch2），继续用零依赖的 `assert` 风格单测，避免给打包引入额外依赖；
- 不在本轮重训语言模型（准确率天花板问题单独立项）。

## 7. 风险

- 快照测试与 LM/dict 版本强绑定：换系统 libime 数据会导致整片 diff，需要在快照头部记录 `LM md5`，不一致时提示「数据变了，不是代码回归」；
- ASan 与 libime 动态库混用可能报 leak（第三方库不释放），只对 `detect_leaks=0` 跑，专注越界/UB；
- chroot 无网，P3 的 fcitx5 主程序安装可能受阻，需提前确认 apt 缓存。
