# 2026年10月19日12时00分-修复空格错误上屏与M3纠错误伤英文-Hermes

## 问题现象

用户反馈：**"第一项后错误跟着用户输入，按空格经常把用户的输入上屏，按1键才正常"**。

即：输入拼音（如 `nihao`、`zhongguo`）后按空格，本应上屏首选候选（你好/中国），却经常把**用户输入的原始拼音**（`nihao`/`zhongguo`）上屏；按数字键 `1` 才正常选候选。

## 根因分析

`fcitx5-addon/pinyinime.cpp` 的 `keyEvent` 空格处理里，**中英自动混输判断用 `is_valid_pinyin(state->rawInput_)`**，而 `rawInput_` 包含隔音符 `'` 和空格：

- 用户输入 `ni'hao`（带隔音符）→ `rawInput_ = "ni'hao"`
- `is_valid_pinyin("ni'hao")` 的 DP 音节切分遇到 `'` 失败 → 返回 **false**（误判为英文）
- 混输条件 `!is_valid_pinyin(...) && rawInput_.size() > 4` 成立（`ni'hao` 6字符 >4）
- → 按空格把 `ni'hao` 原文上屏，而不是候选"你好"

同样 `ni hao`（带空格）、`zhong'guo` 等都会触发。这是**隔音符/空格导致 `is_valid_pinyin` 误判**。

## 修复 1：混输判断改用「紧凑拼音」

在 `pinyinime.cpp` 空格处理中，先把 `rawInput_` 压缩成**只含 a-z 的紧凑串**（去掉 `'` 和空格），再用 `is_valid_pinyin` 判断：

```cpp
std::string compactRaw;
compactRaw.reserve(state->rawInput_.size());
for (char c : state->rawInput_) {
    if (c >= 'a' && c <= 'z') compactRaw.push_back(c);
}
if (!compactRaw.empty() &&
    !is_valid_pinyin(compactRaw) &&
    (ctx.candidates().empty() || compactRaw.size() > 4)) {
    state->commitText(state->rawInput_);
    ...
}
```

这样 `ni'hao` 压缩成 `nihao` → `is_valid_pinyin("nihao")` 返回 true → 不触发英文混输 → 正常选候选"你好"。

## 修复 2：M3 纠错误伤英文（hello/good 被纠成中文）

修复 1 后，英文 `hello`（5字符）仍会走混输上屏英文。但**启用了 EnableCorrect 时，M3 纠错抢先一步**：`should_correct("hello")` 返回 true（含元音、可纠正成 `henli`），把拼音改成 `henli`，`rawInput_` 被同步为 `henli`，`is_valid_pinyin("henli")` 返回 true → 不再走混输 → 空格选候选"狠戾/分离"。

**修复**：中文拼音音节不含任何**双写辅音**（ll/oo/ee/tt/ss/pp/mm/nn 等），而 hello/good/look/apple 等常见英文单词含双写。检测紧凑拼音是否含双写辅音，命中即判定英文：

- 跳过 M3 纠错
- 直接上屏英文

```cpp
const bool englishDoubled =
    !compactRaw.empty() && !is_valid_pinyin(compactRaw) &&
    (compactRaw.find("ll") != std::string::npos ||
     compactRaw.find("oo") != std::string::npos || ...);
```

## 关键经验

- `is_valid_pinyin` 的 DP 只认 a-z 音节，含 `'`/空格会误判 → 判断前先压缩。
- 中文拼音音节**不含双写辅音**，这是区分英文单词（含双写）与拼音的可靠启发式。
- M3 纠错会改变 preedit 和 rawInput_，英文检测必须在 M3 纠错**之前**。
- CLI 有行模式/交互态/批处理多套解码路径，修复需同步所有路径。
