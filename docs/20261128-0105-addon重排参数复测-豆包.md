# addon 重排参数复测（NBest=45）

## 背景

v0.9.212 的 CLI 单字词奖励在 addon 上实测回退，但早期 addon 评测的候选转储只导出前 20 条，容易被误读成“候选池只有 20”。本轮在 NBest=45、默认重排配置下重新做 400 句分层评测（每域 100 句），确认单字词奖励和门限/alpha 是否真的不能迁移。

基线：baike 30%、news 46%、recent 31%、wiki 16%，合计 **30.75% Top1 / 48.0% Top5**。

## 400 句结果

| 配置 | Top1 | Top5 | 结论 |
|---|---:|---:|---|
| v0.9.212 基线 | 30.75% | 48.0% | — |
| 单字词 β=0.4 | 31.0% | 47.0% | +1 句，Top5 -1pp |
| 单字词 β=0.2 | 31.25% | 47.75% | +2 句，Top5 -0.25pp |
| β=0.2 仅长输入（≥30 字母） | 31.25% | 47.75% | 与全量相同，限定长度无效 |
| 关闭重排 base 门限 | 30.5% | 48.75% | Top5 +0.75，Top1 -0.25 |
| 门限惩罚 2.0 | 31.0% | 47.5% | +1 句，Top5 -0.5 |
| alpha=0.35 | 30.5% | 47.25% | 回退 |
| alpha=0.15 | 30.5% | 47.5% | 回退 |

## 全量复测

β=0.2 跑完整 1200 句：**31.0% Top1 / 45.67% Top5**，对比 v0.9.212 的 30.92% / 46.17%，只多 1 句，Top5 回退 0.5pp。按域 baike 31.33、news 40.33、recent 33.67、wiki 18.67；wiki 反而少 1 句。

## 结论

- 单字词奖励在 addon 的 NBest=45 下仍然不能同时改善 Top1 与 Top5，净收益不超过 1 句，属于噪声级，**不接入**。
- 门限、alpha、长输入限定都只是把错误在域间搬来搬去：Top1 略升时 Top5 必降，反之亦然。
- addon 保持 v0.9.212 原逻辑：**30.92% / 46.17% / 86.45%**。
- 评测转储前 20 条的上限只影响 top-k 统计口径，不代表 libime 候选池；后续若要分析完整 45 条，必须先把 `evalCands` 上限调大，且该改动只允许存在于评测路径。
