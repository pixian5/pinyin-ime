## 1. 要解决的具体问题

上一版 `cpp/eval_corpus.txt`（189 条）与 `cpp/abbr_presets.h` 是**同一批提交里互相改出来的**：

- `12585a0`「77%→100%」：源码只改 9 行，却新增 113 行语料；

## 2. 本轮交付

| 文件 | 作用 |
|---|---|
| `bench/leakcheck.py` | 泄漏判定的**唯一实现**：收集 `cpp/*.h`、`cpp/*.cpp` 中含中文字符串字面量（1982 条）、长度≥4 的模板（1025 条）、`abbr_presets.h` 预设（390 条）、两份旧评测语料文本（625 条） |
| `bench/make_holdout.py` | 从 `bench/corpus/{news,wiki,baike,recent}.txt` 抽样，过滤后转连续无声调拼音，产出 `bench/holdout/*.tsv` + `manifest.json` |
| `bench/check_leakage.py` | **独立读盘复核**（不复用生成过程状态），检查零泄漏 + 纯汉字 + 纯 ASCII 拼音 + 跨域不重复，违规退出码 1 |
| `bench/eval.py` | 唯一评测入口：跑 `pinyin_ime_cli --batch --top1`，算句级/字级准确率，写 `summary.json` + `report.md`（含 20 条错例），支持基线门禁 |
| `.gitcode/workflows/ci.yml` | `unit` job 增加泄漏审计与指标自检两步 |

### 语料规格

- 1200 句：news / wiki / baike / recent 各 300
- 长度 6–40 个纯汉字，跨域拼音与文本均不重复
- 与 390 条预设**零交集**、与 1025 条模板**零包含关系**、与旧评测语料**零重叠**
- 抽样种子固定 `--seed 42`，`manifest.json` 记录各域 sha256，可复现

### 门禁阈值

- 句级准确率下降 > **1.0pp** → 退出码 2
- 字级准确率下降 > **0.5pp** → 退出码 2

阈值写在 `bench/eval.py` 顶部常量，改阈值要单独提交。

## 4. 已知局限（写进了 manifest）

1. **未对 LM 训练语料去重**：news/wiki/baike 很可能参与过训练，绝对准确率会偏高；本语料的用途是**版本间回归对比**，不是对外宣传数字。
2. **多音字按 pypinyin 默认读音**：少量句子可能因读音选错而判错，属系统性噪声，对同版本对比影响很小。
3. **只覆盖首选**：暂不评 top5 命中率、逐键延迟；`eval.py` 的 JSON schema 预留了扩展位。
