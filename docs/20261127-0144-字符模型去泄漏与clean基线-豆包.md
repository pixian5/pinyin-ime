## 一、问题

v0.9.197 的 `42.67% / 88.88%` 不可作为真实准确率：

- 1200 句 holdout 的原文 **1200/1200** 全部能在 `bench/corpus` 找到；
- `scripts/train_char_lm.py` 默认用 `bench/corpus/*.txt` 全量训练，holdout 句子直接进入字符 trigram；
- `bench/check_leakage.py` 只查预设/模板/旧评测集，未检查训练语料和模型；
- 结果：字符重排在做“候选里认原句”，不是泛化。

用去掉逐句原文重叠后的模型复测，alpha=2.0 只有 **26.50% / 85.62%**，还低于无重排的 **27.83% / 84.81%**。

## 二、本轮改动

### 2.1 新增清洗脚本

`bench/clean_corpus.py`：

- 以 `bench/holdout/*.tsv` 为固定 test；
- 从 `bench/corpus/*.txt` 删除与 test 逐字相同的句子；
- 再删除与任一 test 句子共享 **>=2 个字符 5-gram** 的训练句；
- 默认排除 `lccc_eval.txt`、`daily.txt`、`dialogue.txt`，不把纯评测语料当 train；
- 输出 `manifest.json`（每文件 sha256、句数、剔除数、test 句数、caveat）。

结果：训练集 **12,130 句 / 257,455 字**；exact 剔除 1,201 句，5-gram 近似剔除 798 句，跳过 3 个 eval-only 文件。

### 2.2 新增泄漏检查

`bench/check_train_leakage.py`：

- 训练目录不得包含 `lccc_eval/daily/dialogue`；
- 训练句与 test 不得逐字相同；
- 训练句与任一 test 不得共享 >=2 个 5-gram；
- 输出机器可读报告，CI 失败即红。

### 2.3 重训字符模型

- `scripts/train_char_lm.py` 新增 `--meta-out` 与 `--alpha` 参数，元数据记录语料文件 sha256、句数、字符数、模型 sha256、版本、alpha；
- 用 clean 语料重训 `data/char_trigram.bin`：词表 3,929，bigram 107,229 条，trigram 203,674 条，2,945,931 字节；
- `cpp/char_lm.h` 的 `kAlpha` 从 2.0 下调到 **0.25**。

alpha 扫描（clean 语料、同 test）结果：

| alpha | 句级 | 字级 |
|---|---:|---:|
| 0.10 | 29.75% | 85.81% |
| **0.25** | **30.00%** | **86.05%** |
| 0.50 | 29.25% | 85.98% |
| 1.00 | 27.92% | 85.77% |
| 2.00 | 26.50% | 85.62% |

0.25 是本轮 clean 语料上的最优；高于 0.5 迅速伤害首选。

### 2.4 新基线

`bench/baseline.json` 前移到 v0.9.198：

| 域 | 句级 | 字级 | P50 |
|---|---:|---:|---:|
| baike | 30.33% | 88.35% | 73.07ms |
| news | 36.33% | 88.83% | 55.11ms |
| recent | 35.33% | 87.71% | 56.52ms |
| wiki | 18.00% | 79.31% | 47.42ms |
| **合计** | **30.00%** | **86.05%** | — |

对比无重排 **27.83% / 84.81%**：clean 字符模型带来 **+2.17pp 句级 / +1.24pp 字级**。这不是“突破”，只是把原来的负收益修正为正收益。

### 2.5 门禁接入

`scripts/ci_build.sh` 现在每次都会：

1. `clean_corpus.py --near-dup-threshold 2` 生成临时训练集；
2. `check_train_leakage.py` 校验无 exact / 5-gram 泄漏；
3. `train_char_lm.py` 从临时训练集确定性重训；
4. `cmp` 重训模型与 `data/char_trigram.bin`，不一致直接失败；
5. `cli_snapshot_test.sh` 与 `bench/eval.py` 使用这次重训出的 `PINYINIME_CHAR_LM`。

这保证“发布模型能从 clean 语料重建”，不再出现 data 目录里的模型来路不明。

## 四、仍然存在的限制

1. **不是文档级 split**：语料在 fetch 阶段已经拍平成句子，没有 doc_id/url；本轮的 exact + 5-gram 近似去重只能消掉逐句原文和明显改写，同文档剩余句子仍可能残留风格泄漏。下一步必须让 `fetch_*` 输出 JSONL（doc_id/url/title/text），按文档切分。
2. **数据许可仍未解决**：`bench/corpus` 仍含 LCCC 研究用途语料、人民网新闻、百度百科、中文维基文本；`data/char_trigram.bin` 仍是这些语料的衍生模型。本轮只修评测口径，不代表可以公开分发模型。
3. **`bench/holdout` 仍是旧 holdout**：它的 1200 句来自旧 corpus；在文档级 split 完成前，clean 数字只能做版本间回归，不能对外宣称绝对准确率。
4. **`e -> 俄` 快照变化**：clean 模型把单字母 `e` 的首选从「哦」改成「俄」。这是模型行为变化，不是崩溃；单字母场景是否需要专门规则，留待用户指标评测决定。

## 五、下一步

1. 让 `bench/fetch_*.py` 输出带 doc_id 的 JSONL，按文档做 train/dev/test；把本轮 `clean_corpus.py` 降级为“句子级兜底”。
2. 在文档级 test 上重跑 alpha 扫描；如果 0.25 仍不能稳定正收益，默认关闭字符重排。
3. 清 LCCC/新闻/百科/维基的再分发边界，补 `docs/DATASETS.md`；在许可未清前不要把模型放进公开 Release。
4. 再做 nbest=45 的 listwise 重排；当前 clean 30.00% 距离 recall@45 的 53.58% 还有很大空间，但必须先有可信 test。
