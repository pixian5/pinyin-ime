# deb 依赖修复与 addon CI 转绿（v0.9.201）

## 问题

v0.9.200 新增的 `addon-acceptance` job 第一次运行在 `Install deb` 一步失败：

```
dpkg: dependency problems prevent configuration of pinyin-ime:
 pinyin-ime depends on libime; however:
  Package libime is not installed.
```

Ubuntu 24.04 的仓库里没有名为 `libime` 的包；实际提供库的是 `libimecore0` / `libimepinyin0`，数据是 `libime-data`。旧 `test_install.sh` 一直用 `--ignore-depends=fcitx5,libime,libime-data` 绕过，因此安装矩阵 30/30 没有发现这个真实用户会遇到的阻断。

## 修复

- `scripts/build_packages.sh` 的 deb 依赖从：
  `fcitx5, libime, libime-data`
  改为：
  `fcitx5, libimecore0, libimepinyin0, libime-data`
  与 `packaging/debian/control` 保持一致；`libime-bin` 会拉起 core/pinyin 库。
- `ci_static.sh` 增加三条守卫：
  - 仍要求存在 `libime-data`；
  - 禁止再出现 `fcitx5, libime, libime-data`；
  - 要求 `libimecore0, libimepinyin0` 存在。
- `addon-acceptance` job 保留正常 `dpkg -i`（失败才 `apt-get -f install`），不再用 ignore-deps 掩盖依赖错误。

## 验证

- 本地重建 deb 后 `dpkg-deb -I` 依赖声明为 `fcitx5, libimecore0, libimepinyin0, libime-data`。
- 本地 chroot 正常 `dpkg -i` 安装/升级成功；随后 `test_addon_phrases.sh` 8/8。
- GitHub Actions 重新跑 `package` + `install-matrix` + `addon-acceptance`；这条链路现在同时验证“包能正常装”和“真实 addon 能上屏”。

## 经验

- 安装矩阵里的 `--ignore-depends` 只能验证文件布局和卸载清单，不能证明包能被普通用户 `apt install`；必须另有一条**不忽略依赖**的安装路径。
- 发行版包名不能凭直觉写（`libime` 在 Ubuntu 不存在）；以 `packaging/debian/control` 或 `apt-cache search` 为准。
