# addon 逐键消歧修复与长句提分（v0.9.203）

## 结论

- v0.9.202 评测的 addon **28.00% / 80.31%** 不是模型上限，是 addon 自身的逐键消歧 bug。
- 修复后 1200 句 addon **30.25% / 86.24%**，错误句从 864 降到 839；baike 从 26.33/71.22 提升到 **31.33/89.01**，wiki 从 16.00/75.46 提升到 **18.67/79.81**。
- P50 从 505.4ms 降到 489.7ms，P95 从 754.3ms 降到 599.1ms，P99 从 1757.2ms 降到 647.5ms。消歧修复同时去掉了长句每键 `ctx.clear()+重打` 的开销。

## 根因

addon 的字母输入分支每键都执行：

```cpp
std::string disambig = disambiguate_if_needed(rawPreedit);
if (disambig != rawPreedit) {
    ctx.clear();
    for (char c : disambig) ctx.type(std::string(1, c));
}
```

`rawPreedit` 只保留当前已输入字母。长句输入到 `...wenxian...` 前，`rawPreedit` 仍是半截拼音；`disambiguate_if_needed` 在“不可完整切分”时会调 `disambiguate_pinyin`，把 `xian` 拆成 `xi'an` 并 **清空重打**。从此 libime 按 `wen xi ' an` 切分，候选变成“文戏安多”而不是“文献多见”。

证据：同一句 `gaicizuizaojianyusanguozhimingdaiwenxianduojian...`

- CLI `--batch --top1`：`该词最早见于三国志明代文献多见去世有利用法清代长高文论及趋势指数`
- 旧 addon：`该词最早见于三国志明代文戏安多渐趋是由利用发情呆帐高温论及趋势指数`（字级 60.61%）
- 修复后 addon：与 CLI batch 一致（字级 78.12%，整句差异只剩同音选择）
- 临时关闭消歧：同样恢复“文献多见”，证明根因不是采集时序或字符重排。

## 修复

`fcitx5-addon/pinyinime.cpp` 的逐键分支只对 **<=4 个字母** 的极短缩写调用 `disambiguate_if_needed`；更长的输入不再逐键清空重打，交给 libime 增量切分。

为什么不是 <=8：1200 句实测 `<=8` 反而降到 **30.08 / 86.18**，说明 5–8 字母的长前缀仍会在部分句子上误拆；`<=4` 最优。代价是 `xianyoud` 这类 5–8 字母的非全拼缩写不再逐键拆分（实测输出“西安有点”），需要后续用提交前消歧或专用 boost 补回。

## 遗留

- `xianyoud` 等 5–8 字母非全拼缩写需要新入口：建议在空格提交前对完整 raw input 做一次 `disambiguate_if_needed`，而不是逐键。
- addon 的 `rawPreedit` 只保留字母，带隔音符/空格混输的消歧仍走旧的 `disambiguate_pinyin`；需要补测。
- 全量 addon 评测仍手动，未进每次 push 的 CI。
