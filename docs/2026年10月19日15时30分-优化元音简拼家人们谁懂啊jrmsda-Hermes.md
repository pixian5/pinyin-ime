# v0.9.113 优化元音简拼：解决"家人们谁懂啊"(jrmsda) 被切分成"三大"的问题

日期：2026年10月19日 15时30分
版本：0.9.113
模型：Hermes

## 问题背景

用户反馈：输入简拼 `jrmsda`（家人们谁懂啊）时，输出的是"家人们三大"而不是"家人们谁懂啊"。

根因分析：
- libime 对简拼 `jrmsda` 的解码切分为 `j r m s da`，把最后的 `d a` 合并成一个音节 `da`（大/打），因为 `da` 是合法拼音。
- 而用户意图是 `j r m s d a`（j=家 r=人 m=们 s=谁 d=懂 a=啊），`a` 作为独立音节"啊"。
- 通过实验确认：即使强制把 `da` 拆成 `d` + `a`（用空格分隔），libime 的 LM 里也没有"家人们谁懂"这个 n-gram，无法生成"家人们谁懂啊"。
- 结论：这类网络热词/口语在 libime LM 中不存在，只能靠 boost 预设表插入。

## 解决方案

### 1. 添加网络热词/口语简拼到 boost 预设表（abbr_presets.h）

在 `abbr_preset_map` 中新增一批网络热词/口语简拼：
- `jrmsda → 家人们谁懂啊`（用户明确要求）
- `jrms → 家人们`、`jrm → 家人们`、`xdm → 兄弟们`
- `srds → 虽然但是`、`yyds → 永远的神`、`xswl → 笑死我了`、`awsl → 啊我死了`（a=啊独立成字）
- `zqsg → 真情实感`、`u1s1 → 有一说一`、`dbq → 对不起`、`bzd → 不知道`
- `gkd → 搞快点`、`zxb → 在不在`、`byy → 不要呀`、`ky → 可以`、`buky → 不可以`

### 2. 放宽简拼长度限制（is_abbreviated_pinyin）

- 原来：长度 2-6。
- 改为：长度 2-10，以支持更长网络热词/句简拼（如 `jrmsda` 6字、更长的口语）。

### 3. 修复英文检测误伤含 `yy` 的简拼

发现 `yyds`、`yy`（应用）被 v0.9.109 的 `englishDoubled` 英文检测误判：
- `englishDoubled` 检测双写辅音（ll/oo/ee/tt/ss/pp/mm/nn 等），其中包含 `yy`。
- `yyds` 含 `yy`（永远两个字的简拼 y+y），被误判为英文，直接上屏 `yyds`。
- 修复：`knownAbbr` 判断——若命中 boost 预设（返回值非空**且不等于输入**）则不判为英文。
  - 注意 `lookup_pinyin_boost("hello")` 返回 "hello"（英文直通），返回值等于输入，不算 knownAbbr，因此 `hello` 仍被识别为英文并直通上屏。
- 同步修改 CLI（两处 `englishLineDoubled`）和 addon（一处 `englishDoubled`）。

## 说明

- 元音（a/o/e/i/u）在简拼中既有"作为拼音一部分"（如 `da` 的 `a`）也有"单独成字"（如 `a`=啊）的双重身份，这是简拼固有的歧义。
- libime 默认按 LM 概率选择切分（`jrmsda` → `da` 合并成"大"）。
- 对 LM 中不存在（或概率极低）的网络热词，**boost 预设表是可靠方案**：插入后首选即出。
- 若用户需要更多这类词，可在 `~/.config/pinyin-ime/abbr.txt` 中自定义（格式 `abbr=词`），或反馈给作者加入预设。
