## 2. 修掉的真问题

### 2.1 三个命令只解析不执行

`--phrase-add` / `--phrase-del` / `--phrase-list` 在帮助里有、参数解析里置了标志位，但**后面没有任何代码使用这些标志**——用户加了快捷词永远不会生效。现在落到 `$userDataDir/custom_phrases.txt`（与 i 模式共用同一份表），支持新增/更新/删除/列出，非法格式退出码 1。

同时删掉 `--clipboard`：剪贴板历史只有库层 `ClipboardHistory` 类和单测，addon 与 CLI 都没有接生产者，属于纯空壳；保留一个假选项比删掉更误导。

### 2.2 云候选回填后 UI 永远不刷新

`kickCloudQuery` 里 `inst->eventLoop().addPostEvent(...)` 的返回值被直接丢弃。fcitx 的这个接口返回 `unique_ptr<EventSource>`，**析构即注销事件**——后台线程查到云候选后投递的「刷新 UI」回调根本不会执行（`-Wall` 的 `nodiscard` 警告正是提示这一点）。现在由 `PinyinIMEEngine::keepCloudRefreshSource()` 持锁保存，生命周期长于 state，不会因为输入上下文销毁而丢事件。

这是本轮最有价值的发现：**警告不是洁癖，nodiscard 警告指向的是真实功能失效**。

### 2.3 编译警告（7 + 4 + 1 条）

- `quick_input_typing.h:458` 运算符优先级（`&&` 在 `||` 内没括号）——加括号；
- `quick_input_stats.h` / `quick_input_ui.h` 未使用参数——`(void)` 标注并说明预留用途；
- `quick_input_cloud.h` `std::system` 返回值被忽略——显式判断；
- `quick_input_core.h` `%04d%02d%02d` 写进 `char[16]` 有截断风险——缓冲扩到 32；
- addon 的 `nodiscard`——见 2.2。

## 4. 踩坑记录（给后来者）

- gcov 对「从未执行」的行写 `#####`，不是 `0`；只按数字解析会把未执行行当成不存在，得出「100% 覆盖」的假象（本轮第一版就踩了）。
- gcov 必须能按记录路径打开源文件，否则只写 4 行头信息；在临时目录跑要给 `cpp/` 建软链，或把绝对路径归一化（`/src/cpp/x` → `cpp/x`）。
- CLI 的数据文件走**位置参数**（`pinyin_ime_cli --batch F lm dict`），不是 `--lm/--dict` 选项；脚本里传错会报「未知参数」。
- chroot 无法 `mount -t proc`（权限不足），ASan 的 LeakSanitizer 直接 fatal；CLI 的 ASan 检查只能在真机/有 proc 的环境跑，chroot 用 UBSan 兜底。
