# GitHub Actions 微软源 403 修复（v0.9.208）

## 现象

v0.9.207 推送后，GitHub Actions run `45961525896`：

- `package`：success
- `install-matrix`：success（30/30）
- `addon-acceptance`：success
- `build-eval`：failure
  - 失败步骤不是编译或评测，而是 `Install build dependencies`
  - `sudo apt-get update` 报：
    `E: Failed to fetch https://packages.microsoft.com/ubuntu/24.04/prod/dists/noble/InRelease 403 Forbidden`
    `E: The repository ... is no longer signed.`
  - 退出码 100。

## 原因

GitHub 的 `ubuntu-24.04` runner 预置了 `packages.microsoft.com` 源；该源当天返回 403，导致任何 `apt-get update` 直接失败。项目本身不依赖微软包，属于 runner 环境噪声，不是代码回归。

## 修复

`.github/workflows/ci.yml` 在 `build-eval` 和 `package` 的 `Install build dependencies` 之前增加：

```yaml
- name: Remove broken Microsoft apt source
  run: |
    sudo rm -f /etc/apt/sources.list.d/microsoft-prod.list \
      /etc/apt/sources.list.d/microsoft-prod.sources
```

只移除微软源，保留 Ubuntu 官方源；项目所需的 cmake/g++/libime/fcitx5 依赖仍从官方源安装。

## 验证

- v0.9.207 本地 `ci_build.sh`、`ci_static.sh`、`test_install.sh` 均通过；CI 失败与这些无关。
- 本修复提交后重跑 `build-eval`，目标是五个 job 全绿（package/install/addon 已在 v0.9.207 验证）。
- `VERSION` 从 0.9.207 升到 **0.9.208**；产品代码/模型不变，仅 CI 依赖安装路径变化。

## 经验

- GitHub runner 的预置 apt 源可能整体 403；`apt-get update` 失败先看具体源，不要先怀疑项目依赖。
- 对无关源做最小移除，不要 `apt-get update || true` 掩盖真实依赖缺失。
