# 发布产物校验清单（v0.9.188）

> 2026-11-26 18:40 · 豆包 · 版本 0.9.187 → 0.9.188

## 1. 问题

v0.9.187 能打出 deb/rpm 了，但 `dist/` 里同时躺着 v0.9.186、v0.9.187、v0.9.121 的旧包和旧 `SHA256SUMS`，没有任何机制说明「哪个文件对应哪个版本、下载后该拿什么比对」。发布物没有校验清单，等于让用户凭文件名信任。

## 2. 改动

`scripts/build_packages.sh` 新增 `write_checksums()`，在 `rpm | deb | all` 三种模式打包+自检之后执行：

- 输出 `dist/SHA256SUMS_v<VERSION>`，只包含**本次实际打出来**的包（`all` 模式含 rpm + deb，单模式只含该种）；
- 旧版本残留文件不进清单；
- 清单直接 `cat` 到日志，便于复制；
- 若没有任何产物则返回非 0，避免生成空清单。

`scripts/ci_static.sh` 增加第 5 条发布工程守卫：`build_packages.sh` 必须包含 `SHA256SUMS_v$VERSION` 逻辑。

## 3. 验证（chroot x86_64，版本 0.9.188）

```
$ cat dist/SHA256SUMS_v0.9.188
b66fe8d58e12617ada354e9b2f6fd09e9bf77d344b4dd92dbf81aa6ce682124f  pinyin-ime-0.9.188-1.x86_64.rpm
0727aeb0d0bc1338ef5ae74f45c74d543654d6ec06172c863a2fcbd99b42df5a  pinyin-ime_0.9.188_amd64.deb

$ sha256sum -c SHA256SUMS_v0.9.188
pinyin-ime-0.9.188-1.x86_64.rpm: OK
pinyin-ime_0.9.188_amd64.deb: OK
```

`dist/` 里同时存在 0.9.186/0.9.187/0.9.121 的旧产物，但清单只列 0.9.188 两个文件——正是预期行为。

产物：`pinyin-ime-0.9.188-1.x86_64.rpm` 22,743,929 B、`pinyin-ime_0.9.188_amd64.deb` 22,734,334 B。
