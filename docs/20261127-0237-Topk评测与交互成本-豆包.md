# Top-k 评测与交互成本（v0.9.199）

## 为什么做

v0.9.198 的评测只喂 `--top1`，只能回答“首选对不对”，回答不了：

- 用户实际面对的是候选列表，目标句排第 2/3/10 时体验差多少；
- 扩到 addon 默认 `nbest=45` 到底改善首选，还是只把目标句埋得更深；
- 翻页、数字选择的成本有多高，值不值得继续扩池。

所以 v0.9.199 把 `bench/eval.py` 改成一次批量取 `--top-k 10`，在原有句级/字级之外增加排名与交互成本指标。

## 实现

- `run_cli()` 从 `--top1` 改为 `--top-k 10`，CLI 每行输出 Tab 分隔候选；新增 `--nbest`（默认 10）控制候选池。
- `rank_metrics()` 计算：
  - Top1 / Top3 / Top5 / Top10：参考句是否进入前 k；
  - MRR：命中排名倒数均值，未命中记 0；
  - 命中平均排名：只在命中的句子上统计；
  - 命中后平均按键 / 翻页率：按 CLI 每页 5 个候选保守估算，首选或 2–5 名算 1 键，第 6 名起每页 +1 键。
- `summary.json` 每个域和 overall 都带 `rank`；`report.md` 增加“候选排名与交互成本”表。
- 自检覆盖空输入、MRR、平均排名、按键估算；`--baseline` 仍只比句级/字级，排名指标暂不做门禁。

## 结果（clean 模型，1200 句）

### nbest=10（与现有基线同池）

| 指标 | 合计 |
|---|---|
| 句级首选 / 字级 | **30.00% / 86.04%** |
| Top1 / Top3 / Top5 / Top10 | 30.00% / 40.25% / 43.58% / **46.08%** |
| MRR | 0.358 |
| 命中平均排名 | 1.87 |
| 命中后平均按键 | 1.05 |
| 命中后翻页率 | 5.42% |
| 未进 Top10 | 647 句 |

Top10 的 46.08% 与 v0.9.180 的 recall@10 完全对上，说明这次改动没有改变候选池，只是把已有候选的排名暴露出来。

### nbest=45（贴近 addon 默认）

| 指标 | 合计 |
|---|---|
| 句级首选 / 字级 | **30.33% / 86.24%** |
| Top1 / Top3 / Top5 / Top10 | 30.33% / 41.67% / 45.33% / **48.92%** |
| MRR | 0.371 |
| 命中平均排名 | 3.67 |
| 命中后平均按键 | 1.39 |
| 命中后翻页率 | 39.04% |
| 未进 Top10 | 557 句 |

结论：

- 扩到 45 只把首选从 30.00% 提到 30.33%（+0.33pp），Top10 从 46.08% 提到 48.92%（+2.84pp）；
- 代价是命中句的平均排名从 1.87 掉到 3.67，翻页率从 5.42% 涨到 39.04%，命中后按键从 1.05 涨到 1.39；
- **Top1 仍是瓶颈**，继续扩池主要是在“让正确答案有位置”，不是在“让正确答案排第一”。下一步应优先做能提高首选排序的信号（LM/上下文/词级特征），而不是无限扩 nbest。

## 已知限制

- 仍是 CLI 口径；addon 的候选窗、每页数量、翻页键与 CLI 不同，addon 真实交互成本未单独测。
- 按键/翻页是保守估算，不是真实 GTK 事件计数；没有逐句 P50/P95/P99 延迟。
- 还没有 2–6 字词/短语级 gold，当前指标仍是整句级。
- 排名指标没有进基线门禁，避免历史基线缺少 `rank` 字段时误报；等稳定后再加。
