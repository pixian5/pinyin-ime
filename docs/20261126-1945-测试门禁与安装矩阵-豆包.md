# 测试门禁与安装矩阵脚本化（v0.9.191）

> 2026-11-26 19:45 · 豆包 · 版本 0.9.190 → 0.9.191
>
> 方案文档：`docs/20261126-1920-测试开发升级方案-豆包.md`（P0 阶段落地）

## 1. 为什么先做这一层

0.9.189 之前的「验证」都是我手工敲命令、看输出：dpkg 要不要 `--force-overwrite`、升级后 `sc.dict` 还在不在、`--version` 报的是不是包版本——全是肉眼判断。这类问题一旦出现在真实用户机器上，代价是「装完输入法不能用」。P0 的目标是让**安装路径和 CLI 行为都变成可断言**的。

## 2. 新增三件套

### 2.1 `scripts/test_install.sh`（安装矩阵）

一条命令跑完 deb / rpm / runtime 三条路径，25 项断言：

- SHA256 清单逐项匹配；
- deb：`dpkg -i` 后状态、版本、`Depends` 含 `libime-data`、**不含** LM/dict、`--version` 与 VERSION 一致、无参数解码 `nihao→你好`；
- rpm：`rpm -i` → 注册版本、文件列表含 addon、无 LM/dict、解码冒烟 → `rpm -e` 干净卸载、addon 不残留；
- runtime：`install.sh` → 解码冒烟 → `uninstall.sh` → CLI/addon 移除、`sc.dict` 未被误删。

chroot 里 fcitx5/libime 包名不可满足，脚本会自动在「忽略依赖」模式下重试并明确标注，不会掩盖真实发行版环境下的依赖问题。

实测结果：**通过 25 / 失败 0**。

### 2.2 `scripts/cli_snapshot_test.sh` + `bench/snapshots/`

42 例固定输入（全拼/简拼/混输/英文直通/数字/单字母/标点/歧义音节/日期触发词），逐条比对 top1。每次运行使用全新临时 user-data，避免自学习污染。

- 期望文件头记录 `lm_md5`/`dict_md5`，数据版本变了会提示「这属于数据变化，不一定是代码回归」；
- `--update` 重写期望值；负面测试（手改一条期望）能准确报出 `'nihao': 期望 '您好' 实际 '你好'` 并以 1 退出；
- 快照锁定的是**当前行为**（包括 `womenzaiyonglibimezuoceshi→我们在用利弊么左侧是` 这种不理想切分），它只用于防回归，不代表这些结果是对的。

### 2.3 `scripts/release_check.sh`（发布门禁）

把发版前人工确认的六处一致性变成断言：VERSION ↔ CHANGELOG ↔ README ↔ 文档索引 ↔ CLI 二进制 ↔ addon 配置，外加基线版本提醒、`ci_static.sh`、单测、快照。`--full` 追加安装矩阵与 chroot 准确率评测。任何一项失败即拒绝发布。

## 3. 验证

- `bash scripts/test_install.sh --skip-build`：25/25 通过；
- `bash scripts/cli_snapshot_test.sh`：42/42 一致；篡改期望值后按预期失败；
- 打包产物体积：deb 999,400 B、rpm 1,008,764 B、runtime 22,731,607 B（runtime 仍自包含数据）。

## 4. 局限

- 快照用例绑定 LM/dict，换模型数据要整片更新；
- 安装矩阵在 chroot 内验证的是「文件落位 + 默认路径可解码」，不是真机 GUI 加载；
- `release_check.sh` 的二进制/快照项需要编译产物，纯文档改动时可以只依赖静态部分。
