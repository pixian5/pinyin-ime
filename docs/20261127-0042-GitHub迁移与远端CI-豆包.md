# 迁移到 GitHub 并恢复远端 CI

- 日期：2026-11-27 00:42
- 模型：豆包

## 背景

GitCode 与 AtomGit 是同一平台的两个网址，两个域名的仓库都没有 Actions 入口；此前 5 条流水线记录只是后端 `VALIDATION_ERROR`，不会真正执行。因此 v0.9.196 删除了无效 workflow，只保留本地 `scripts/ci_build.sh`。

用户要求改为 `github.com`。GitHub 有可用的 Actions，且本机 `gh` 已登录 `pixian5`（token 含 `repo` / `workflow` 权限），所以本轮把仓库镜像到 GitHub，并恢复远端 CI。

## 仓库与远端

- GitHub：`https://github.com/pixian5/pinyin-ime`
- GitCode：`https://gitcode.com/laotongtian/pinyin-ime`（保留为备份远端，不再作为 CI 平台）
- Mac 仓库远端：

```text
origin   https://github.com/pixian5/pinyin-ime.git
gitcode  https://gitcode.com/laotongtian/pinyin-ime.git
```

`main` 已推送到 GitHub，并设置 upstream 为 `origin/main`。

## GitHub Actions

新增 `.github/workflows/ci.yml`：

- 触发：push 到 `main`、PR、手动 `workflow_dispatch`。
- 运行环境：`ubuntu-24.04`。
- 依赖：`libime-*`、`libfcitx5*-dev`、Boost、libcurl、cmake、g++、python3。
- 步骤：
  1. `bash scripts/ci_static.sh`：仓库卫生、文档、版本与废弃 workflow 检查；
  2. `bash scripts/ci_build.sh`：编译 CLI/addon、721 条单测、警告、42 例快照、fuzz、1200 句评测与基线门禁。
- `concurrency` 按 ref 分组，新的 push 会取消同分支旧任务。
- `permissions: contents: read`，不需要任何 secrets。

## 为什么不是直接把 GitCode workflow 改个域名

GitCode/AtomGit 后台没有 runner，YAML 字段再正确也不会执行；只有换到真正提供 Actions 的平台才有意义。GitHub 的 runner 是独立干净环境，能补上本地门禁的两个短板：人工漏跑、本机环境污染。

## 已知限制

- GitHub Actions 只跑静态检查 + 编译 + 单测 + 快照 + fuzz + 1200 句评测；**安装矩阵和真实 fcitx5 上屏仍只在本地跑**，因为需要 dpkg/rpm/Xvfb/GTK 等额外环境，后续可拆成单独的 workflow。
- GitCode 仍保存旧提交；以后双远端推送用：

```bash
git push origin main
git push gitcode main
```

- GitHub 仓库当前为 public；如果以后要转 private，Actions 免费额度会受账户套餐限制。

## 验证

- 首次 push 后需要在 GitHub Actions 页面确认 `CI` 工作流真实跑通；若依赖包名或路径与 chroot 不同，按日志修正 workflow。
- 本地仍以 `bash scripts/ci_build.sh` 为唯一可信门禁；远端 CI 通过不代表安装矩阵/真实上屏通过。
