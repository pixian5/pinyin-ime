# 发布工程：架构自适应 + 首次在 x86_64 打出 deb/rpm（v0.9.187）

> 2026-11-26 18:35 · 豆包 · 版本 0.9.186 → 0.9.187

## 1. 问题：发布工程停在 v0.9.121，而且写死了 aarch64

体检里 P1「发布工程停在 v0.9.121」一直没动。这次实际跑打包链路，撞到两个硬伤：

1. `scripts/build_packages.sh` 里 `ARCH_RPM=aarch64`、`ARCH_DEB=arm64`、deb 的 addon 安装目录写死 `/usr/lib/aarch64-linux-gnu/fcitx5`。在 x86_64 机器上打出来的包名和 `.so` 安装位置全错，fcitx5 装完也找不到 addon。
2. `packaging/pinyin-ime.spec` 里 `BuildArch: aarch64`。x86_64 上 `rpmbuild` 直接报 `No compatible architectures found for build`，一个包都出不来。
3. 数据文件默认指向仓外的 `pinyin-ime-s3/v0.9.116` 快照；换台机器必然「缺文件: zh_CN.lm」。构建产物（CLI/addon/conf）路径也写死成仓内 `cpp/build`、`fcitx5-addon/build`，out-of-tree 构建无法打包。

## 2. 改动

| 文件 | 改动 |
| --- | --- |
| `scripts/build_packages.sh` | 用 `uname -m` 推导默认架构（x86_64→rpm `x86_64` / deb `amd64` / addon 目录 `x86_64-linux-gnu`；aarch64→`aarch64` / `arm64` / `aarch64-linux-gnu`），`ARCH_RPM` / `ARCH_DEB` / `FCITX5_LIBDIR` 可覆盖；`CLI` / `ADDON_SO` / `ADDON_CONF` 可覆盖（支持 out-of-tree）；数据文件改为 `DATA_DIR` 或 `LM`/`DICT`，缺省自动探测 `/usr/share/libime/zh_CN.lm` 与 `/usr/lib/*/libime/zh_CN.lm` |
| `packaging/pinyin-ime.spec` | `BuildArch: aarch64` → `BuildArch: @ARCH@`，由打包脚本按 `ARCH_RPM` 替换 |
| 同上（rpm 调用） | `rpmbuild` 增加 `--target "$ARCH_RPM"`，交叉打包时不再依赖宿主默认架构 |
| `scripts/ci_static.sh` | 新增 4 条发布工程守卫：必须 `uname -m` 推导、不得写死 `ARCH_RPM=aarch64`、spec 必须用 `@ARCH@`、`FCITX5_LIBDIR` 必须可覆盖 |

## 3. 实测（Ubuntu 24.04 chroot，x86_64）

构建：CLI `cpp/build/pinyin_ime_cli`（1,460,368 B）+ addon `fcitx5-addon/build/libpinyinime.so`（1,169,720 B）+ 自动生成的 `pinyinime.conf`（`Version=0.9.187`）。

打包（`LM=/usr/lib/x86_64-linux-gnu/libime/zh_CN.lm DICT=/usr/share/libime/sc.dict bash scripts/build_packages.sh all`）：

| 产物 | 大小 | 校验结果 |
| --- | --- | --- |
| `dist/pinyin-ime_0.9.187_amd64.deb` | 22,734,250 B | `dpkg-deb -I`：Version 0.9.187 / Arch amd64；md5sums 8 条全通过 |
| `dist/pinyin-ime-0.9.187-1.x86_64.rpm` | 22,743,733 B | `rpm -qip`：Version 0.9.187 / Arch x86_64 / License LGPL-2.1-or-later |

deb 内容核对（`dpkg-deb -c` + 解包读 conf）：

```
./usr/bin/pinyin_ime_cli
./usr/lib/x86_64-linux-gnu/fcitx5/libpinyinime.so   ← 目录已随架构正确
./usr/share/fcitx5/addon/pinyinime.conf            ← Library=libpinyinime, Version=0.9.187
./usr/share/fcitx5/conf/pinyinime.conf
./usr/share/fcitx5/inputmethod/pinyinime.inputmethod
./usr/share/libime/sc.dict (3,170,345 B) / zh_CN.lm (22,138,741 B)
./usr/share/doc/pinyin-ime/README.md
```

rpm 内容（`rpm -qlp`）同样包含 `/usr/lib64/fcitx5/libpinyinime.so` 与两个数据文件；`.build-id` 目录是 rpmbuild 自动生成的，不影响加载。

## 4. 未验证 / 遗留

- **没有做真机安装验证**：chroot 里没有 fcitx5 主程序与桌面会话，`dpkg -i` 之后的加载、候选窗、输入行为都未测；只验证到包结构与元数据。
- **aarch64 原生包未重测**：架构分支逻辑与 x86_64 相同，但没有在 M 系列 Mac 的 Linux 环境实跑。
- 包内 `Depends: fcitx5, libime` 仍是粗粒度依赖，没有写 `libimepinyin`/`libfcitx5core` 的具体包名（Debian 与 RPM 发行版命名不同，属发布工程后续细化）。
- `scripts/build_release.sh` 与 S3 上传链路未动，仍按 v0.9.121 的目录约定；下一步要把 `dist/` 产物接到发布脚本并更新 `SHA256SUMS`。
