# v0.9.211 CLI 长句候选池扩到 60

## 结论

- CLI 默认 1200 句 Top1 从 **377/1200（31.42%）** 提到 **383/1200（31.92%）**，净增 **6 句**，短输入快照 42 例零差异。
- 只对 **>=54 个拼音字母（约 18 个音节）** 的长输入把重排池从 10 扩到 60；短输入仍保持 10，避免 `e` 这类单键输入被更远候选顶掉。
- addon 侧候选池 50/60/70 全量实测均回退，因此 addon 默认 NBest 保持 **45** 不变。

## 为什么不是全局 NBest=60

- CLI 固定 NBest=60 全量 1200 句为 **386**（比 383 多 3 句），但 42 例快照中 `e` 从「俄」变成「娥」。
- 定位后确认增益集中在长句：固定 60 的 3 个额外 gain 长度分别为 116/69/86 字母；短句反而出现 4 个丢失。
- 因此采用「长句 60、短句 45/10」的动态策略，既吃长句收益，又锁住短输入行为。

- addon 仍保持 NBest=45，不随 CLI 改动。

## 其他已证伪方向

- 多切分候选并集（按音节插入 `'` 强制另一种切分）：nbest45 recall 仅 535→536（+1 句），不足以进入首选。
- BeamSize=50：recall 643→638，反而 -5；Top1 代理分数 +13 但正确候选没有新增。
- 线性重排（base/char/lm/uni/wordCount 随机搜索）按域留一验证：baike 变差，其余最多 +1pp，不稳定。
- 逻辑回归重排：留一域测试 baike 28.33%、news 34.67%、recent 35.67%、wiki 17.67%，全面低于基线。
