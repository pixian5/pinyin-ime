# 夜间 CI 启动超时修复（v0.9.206）

## 现象

v0.9.205 手动触发 `addon-full-eval`，job 在 GTK harness 启动阶段失败：

```
RuntimeError: 等待 addon harness 输出超时（5s）
```

`fcitx5` 和 deb 安装都成功，失败发生在 `app_q` 等首行输出；本地 chroot 首行通常在 1s 内到，GitHub runner 上 GTK im module 首次加载更慢。

## 修复

`scripts/eval_addon_batch.py` 首次等待从 5s 放宽到 20s，后续 9 次仍用 5s；不再用固定 5 次、每次 5s 的循环。总等待上限约 65s，正常启动不受影响。

## 验证

- 本地 py_compile 通过；chroot 内 4 句功能集仍正常。
- 推送后重新 `workflow_dispatch`，确认 1200 句 job 能跑到评测结束。
- 若仍失败，下一步把 `app.log` / `fcitx5.log` 作为 artifact 上传，而不是只看 harness 超时。
