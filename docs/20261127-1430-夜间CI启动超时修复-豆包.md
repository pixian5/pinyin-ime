# 夜间 CI 启动超时修复（v0.9.206）

## 现象

v0.9.205 手动触发 `addon-full-eval`，job 在 GTK harness 启动阶段失败：

```
RuntimeError: 等待 addon harness 输出超时（5s）
```

`fcitx5` 和 deb 安装都成功，失败发生在 `app_q` 等首行输出；本地 chroot 首行通常在 1s 内到，GitHub runner 上 GTK im module 首次加载更慢。

## 修复

`scripts/eval_addon_batch.py` 首次等待从 5s 放宽到 20s，后续 9 次仍用 5s；不再用固定 5 次、每次 5s 的循环。总等待上限约 65s，正常启动不受影响。

## 验证

- 本地 py_compile 通过；chroot 内 4 句功能集仍正常（Top1 75.0%，与 sent_acc 一致）。
- **2026-11-27 06:52 UTC**，手动 `workflow_dispatch` 运行 `45953471461`，`addon-full-eval` **success**，总耗时 **8m49s**（06:43:11→06:52:00），45 分钟 timeout 余量充足。
- 1200 句结果与 v0.9.204 本地一致：Top1 30.25%、Top5 45.17%、Top10 49.83%、MRR 0.3689、字级 86.24%；P50 383.2ms、P95 554.6ms、P99 677.5ms。
- 报告 artifact：`addon-full-25eb58f...`；未再出现 harness 首行超时。
