# 2026年10月19日01时05分-Ubuntu2404-x86_64全平台打通与fcitx5-5.1.7兼容适配-Hermes

## 本轮目标

在全新 Ubuntu 24.04 x86_64 机器（NAT 出口 110.42.235.24）上把 pinyin-ime 做成「真正能跑起来的输入法」。此前所有预构建产物（S3 v0.9.103）均为 aarch64，本机无法直接用，全部从源码构建 x86_64 版本。

## 一、环境与依赖

- Ubuntu 24.04.4 LTS x86_64，g++ 13.3，cmake 3.28（sudo apt 可写 /usr，非只读沙箱）。
- apt 安装：libimecore-dev / libimepinyin-dev / libimetable-dev（1.1.5）、libfcitx5core-dev 等（5.1.7）、libxcb-imdkit-dev、libboost-iostreams-dev、libx11-dev、libxtst-dev、extra-cmake-modules。
- 注意：Ubuntu 仓库没有 fcitx5-dev / libime-dev 元包，实际包名是 libfcitx5core-dev / libimecore-dev 等。
- 密钥写入 ~/.secrets/gitcode.env、~/.secrets/cst-s3.env（chmod 600）；rclone 配置写入 ~/.config/rclone/rclone.conf（cst 远程，注意 secret 含 `=`/`+`/`/`，不能走 rclone 连接串内联，必须用配置文件）。
- 公网 IP：`curl -s ip.sb` → 110.42.235.24，已附 ip.txt 顶部。

## 二、S3 预构建产物（校验通过但架构不符）

- rclone lsd cst:xbz/pinyin-ime/ 最新 v0.9.103；copy 到 pinyin-ime-s3/，sha256sum -c SHA256SUMS 全 OK。
- 但 libpinyinime.so / pinyin_ime_cli / .deb / .rpm 全是 **aarch64**（file 确认），x86_64 机器只能源码重编。

## 三、x86_64 源码构建与 libime 1.1.5 兼容适配

上游代码按新版 libime（≥1.1.9?）API 写，本机 libime 1.1.5 缺少若干枚举/类型，全部做兼容处理（不破坏新版编译）：

1. `cpp/pinyin_ime_cli.cpp`：
   - 补 `#include <libime/core/historybigram.h>`（1.1.5 的 UserLanguageModel::history() 返回不完整类型，需显式包含才能调 add()/dump()）。
   - PinyinFuzzyFlag::L_R、Correction 枚举 1.1.5 没有 → 注释跳过（纠错由自研 M3 pinyin_corrector 兜底）。
   - ShuangpinBuiltinProfile::GB 1.1.5 没有 → "gb" 回退 Xiaohe 并打提示。
2. `fcitx5-addon/CMakeLists.txt`：
   - fcitx5 5.1.x 已移除 `add_fcitx5_addon` 宏（旧版在源码树 src/lib/fcitx-utils/Fcitx5Macros.cmake，新源码 5.0.14/5.1.7 都没有）→ 加 `if(NOT COMMAND add_fcitx5_addon)` 兼容函数（MODULE 库 + lib 前缀 + FCITX_ADDON_TYPE=SharedLibrary）。
   - 仓库新增 `cmake/Fcitx5Macros.cmake`（从 fcitx5 5.1.7 源码 tarball 提取，gh-proxy 下载），CMAKE_MODULE_PATH 指入。
3. `fcitx5-addon/pinyinime.cpp`：
   - L_R/GB 同上处理。
   - `CommonCandidateList::setCursorIndex()` 5.1.7 没有（1.1.17 时代 API）→ 首候选场景直接删（新列表光标默认 0）；candFocus_ 场景用 `nextCandidate()` 循环移动（最多 9 步）。
   - `FCITX_ADDON_FACTORY_V2(name, factory)` 5.1.7 没有 → 用经典 `FCITX_ADDON_FACTORY(factory)`（只带一个参数，导出 C 符号 fcitx_addon_factory_instance）。

## 四、e2e 全过程（Xvfb :91 + 系统 fcitx5 5.1.7 + XIM）

- 编译 xim_test_client（-lX11 -lXtst）。
- 部署：`~/.local/lib/fcitx5/libpinyinime.so`（FCITX_ADDON_DIRS 首位）、`~/.local/share/fcitx5/addon/pinyinime.conf`（sed 替换 @FCITX_ADDON_TYPE@=SharedLibrary / 版本 / core 版本）、`~/.local/share/fcitx5/inputmethod/pinyinime.conf`（Name/Icon/Label/LangCode=zh_CN/Addon=pinyinime）、`~/.config/fcitx5/conf/pinyinime.conf`（DataDir=/usr/share/libime，EnableCorrect=True）。
- 数据路径差异：Ubuntu 的 zh_CN.lm 在 `/usr/lib/x86_64-linux-gnu/libime/zh_CN.lm`，sc.dict 在 `/usr/share/libime/sc.dict`（aarch64/openEuler 两者都在 share 下）。
- **关键踩坑：fcitx5 启动/重启时会把 `~/.config/fcitx5/profile` 重写**——手写的 DefaultIM=pinyinime 被覆盖成内置 `pinyin`，导致 XIM 测试一直打到 fcitx5-chinese-addons 的内置拼音上（现象：senme→森么、zhing→指南宫，自研 M3 纠错完全不触发，debug 日志证实 keyEvent 空格分支没走到我们的 addon）。修复：先 `pkill -x fcitx5` 再写 profile 再启动。**这是新机器部署最容易踩的坑。**
- 最终 XIM e2e 11/11 全过：nihao→你好、zhongguo→中国、zg→中国（简拼）、bjdx→北京大学（简拼）、woshiyige→我是一个、senme→什么（M3）、zhing→中、zhng→中、zongguo→中国、标点，/。全部正确。
- CLI 同机验证：全拼/简拼/纠错/模糊音（cifan→吃饭）行模式全对。
- addon 加载日志确认：`pinyinime: loaded lm=/usr/lib/x86_64-linux-gnu/libime/zh_CN.lm dict=/usr/share/libime/sc.dict`、`Found 1 input method(s) in addon pinyinime`。
