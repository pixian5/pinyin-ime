# addon 单音节候选排序随进程随机旋转问题（2026-09-29 根因定位）

## 现象

Fcitx5 pinyinime addon 的**单音节**候选排序在**不同 fcitx5 进程间随机变化**，而同一进程内稳定：
以输入 `yi` 为例，正确的排序（CLI / 独立复现程序 / libime 直接调用）是

```
一 以 已 亦 易 宜 意 依 矣 亿 乙 义 异 医 衣 …
```

但 addon 连续 5 次 fresh 重启（每次全新用户数据目录）得到 5 种不同排序：

```
一 已 亦 易 宜 意 依 矣 亿 以 益 乙
一 以 已 亦 易 宜 意 依 矣 亿 益 乙   ← 正确
一 亿 以 已 亦 易 宜 意 依 矣 益 乙
一 矣 亿 以 已 亦 易 宜 意 依 益 乙
一 依 矣 亿 以 已 亦 易 宜 意 益 乙
```

它们都是「正确排序」的**循环移位（旋转）**；首字 `一`（首选）始终不变。

## 关键证据（逐项排除法）

| 假设 | 实验 | 结论 |
|---|---|---|
| nbest 不同 | CLI 行模式 nbest=5/20/45 | 排序与 nbest 无关（全一致） |
| locale 不同 | repro 分别 LANG=C/zh_CN.utf8/en_US.utf8 | 排序与 locale 无关 |
| symlink 路径 | repro 用真实路径 vs /usr/lib64/libime 软链 | 排序一致 |
| 用户数据污染 | 全新 UserDataDir + 清空 ~/.local/share | 依旧旋转 |
| 并发竞态 | 同进程内单 IC 连续「输 yi→Esc」×3 dump | 3 次**完全一致** → 非竞态 |
| 独立进程稳定性 | repro / CLI 各连跑 20/6 次 | 20/20 + 6/6 全一致（确定） |

结论：**addon 侧是「进程级」不确定（ASLR 依赖），而 libime 在独立进程里是确定的**。根因指向
Fcitx5 进程内 libime 格点 n-best 生成时，某个依赖**内存地址（ASLR）的哈希/堆迭代顺序**参与了对
「得分相同/相近」候选的排序（表现为旋转）。

## 影响面（诚实评估）

- 只影响**单音节同音字第 2 名以后的排名**；整句首选、句子级输入质量不受影响
  （`nihao→你好`、`woshiyige→我是一个` 等 14/14 稳定，`smoke_test` 20/20 稳定）。
- 用户按「yi + 数字」盲打选字时，同一个字可能在不同会话里出现在不同数字位（肌肉记忆失效）。

## 与上一轮「翻页竞态」的关系（更正）

上一轮把「`=` 翻页后立即按数字结果漂移」归因于「XIM 异步键投递竞态」——**该判断不准确**。
根因实为本问题：`=` 翻页后按数字选中的索引 `idx=9` 每次都稳定，漂移的是 `idx=9` 上那个**字**，
因为候选排序本身在变。故 addon 侧单点翻页+选字的断言不可依赖「具体字」，只能用 net-0 往返用例。

   得分是否也随进程变（若得分确定、仅顺序变，则锁定在 n-best 生成的排序/比较器；若得分也变，
   则更上游）。
2. **候选修复**：在 libime 候选比较器里补**稳定 tie-break**（按 pinyin/UTF-8 字节序），使排序

3. 修复后再把 addon 单音节翻页选字的确定性断言补回 `xvfb_ime_test.sh`。
