# Git 历史重写：清除大文件、仓库瘦身 237MB → 4.4MB

- 撰写模型：deepseek-4.1-flash
- 类型：重大操作（不可逆，已备份）
- 影响范围：整个仓库的全部提交历史（335 个提交 hash 全部改变）

## 一、背景与问题

仓库 `.git` 膨胀到 **237MB**，`git clone` 需要下载大量历史二进制，消耗流量（维护者流量有限，明确要求不要让二进制入库）。

用 `git rev-list --objects --all` + `git cat-file` 统计历史中最大的 blob，元凶如下：

| 体积 | 路径 |
| --- | --- |
| 63.2 MB | `pinyin-ime-s3/pinyin-ime-0.9.77.tar.gz` |
| 34.2 MB | `pinyin-ime-s3/v0.9.84a/releases/pinyin-ime-v0.9.84a.tar.gz` |
| 32.8 MB | `pinyin-ime-s3/pinyin-ime-0.9.77-bin.tar.gz` |
| 31.9 MB | `dist/pinyin-ime-0.9.87-1.oe2203.aarch64.rpm` |
| 30.1 MB | `dist/pinyin-ime-0.9.70-1.oe2203.aarch64.rpm` |
| 30.1 MB | `dist/pinyin-ime-0.9.63-1.oe2203.aarch64.rpm` |

其余零散：`fcitx5-addon/build-debug/`、`fcitx5-addon/build-x11/` 的 `.o` / `.so` 编译中间物，根目录 `pinyin_ime_cli`（多个历史版本各 0.7MB）、`dist/*.so`、`tools/*.so` 等。

合计约 **220MB** 均为二进制/构建产物，属于历史遗留误提交。

## 二、处理方案（两步走）

### 方案 1（已完成，提交 0966399）
- `.gitignore` 追加忽略：`dist/pinyin_ime_cli`、`dist/libime_bench`、`dist/pinyin_corrector_test`、`dist/*.so`、根 `pinyin_ime_cli`、`fcitx5-addon/*.so`、`tools/*.so`、`pinyin-ime-s3/`。
- `git rm --cached` 把已跟踪的二进制移出索引（本地文件保留）。
- 效果：**以后**的 push/pull 不再传输这些二进制；但远程历史里的旧对象仍在，全新 `git clone` 仍会下载。

### 方案 2（本次执行，提交 21ec6f9）
用 `git filter-repo` 重写全部历史，从每一个提交中彻底移除上述路径。

## 四、执行步骤（可复现）

```bash
# 0. 确保工作区干净
git status --short

# 1. 备份
git clone --mirror . /Users/x/code/pinyin-ime-backup-20261029.git

# 2. 安装工具（macOS / brew）
brew install git-filter-repo     # 本次安装 2.47.0

# 3. 重写历史（移除大文件，保留其余）
git filter-repo --force --invert-paths \
  --path dist/pinyin_ime_cli --path dist/libime_bench --path dist/pinyin_corrector_test \
  --path-glob 'dist/*.rpm' --path-glob 'dist/*.deb' --path-glob 'dist/*.so' \
  --path pinyin_ime_cli \
  --path pinyin-ime-s3 \
  --path-glob 'fcitx5-addon/*.so' \
  --path fcitx5-addon/build-debug --path fcitx5-addon/build-x11 \
  --path-glob 'tools/*.so'

# 4. 清理旧对象
git reflog expire --expire=now --all
git gc --prune=now --aggressive

# 5. filter-repo 会自动移除 origin，需重新挂上并强推
git remote add origin https://gitcode.com/laotongtian/pinyin-ime.git
git push --force origin main
git push --force origin --tags
```

## 六、后续注意事项 / 风险

1. **所有协作者必须重新 clone**。旧 clone 的提交 hash 已不存在，直接 `git pull` 会混乱、`git push` 会被拒。
2. **GitCode 服务端旧 pack 可能滞后回收**：force push 后远程 refs 已指向新历史，新 `git clone` 只拉取新 refs 可达对象（约 5MB），不会下载旧大文件；但服务器磁盘上的旧对象可能要等平台自身 GC 才彻底释放。
3. **本地需要重新构建的产物**：本次只是删历史/索引，本地工作区的二进制仍在；若要重新生成，运行 `bash scripts/build_ubuntu_multiarch.sh`（Ubuntu 双架构）或 `make build`。
4. **`pinyin-ime-s3/` 整目录**已从历史移除，若某次需要旧包，从 CSTCloud S3 用 `rclone copy cst:xbz/pinyin-ime/...` 重新下载。
5. **备份目录** `/Users/x/code/pinyin-ime-backup-20261029.git` 确认无用后可删除，以回收约 237MB 磁盘（当前磁盘 94% 使用，建议确认稳定后再删）。
6. 以后严禁把二进制/构建产物提交入库：`.gitignore` 已覆盖 `dist/*.rpm|deb|so`、`pinyin-ime-s3/`、各 `.so`、CLI/bench/test；新增大产物提交前先 `git status` 确认。
