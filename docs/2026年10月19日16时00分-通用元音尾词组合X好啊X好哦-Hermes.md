# v0.9.114 通用元音尾词组合：任意"…辅音元音"简拼都能出"X好啊/X好哦"

日期：2026年10月19日 16时00分
版本：0.9.114
模型：Hermes

## 问题背景

用户反馈：不要局限于 `jrmsda`（家人们谁懂啊）这一个例子。例如【好啊、好哦】……都是相同的处理方式。

即：**通用地**，当简拼串以"辅音+元音"结尾（如 `jrmsha`、`jrmsho`、`xdmha`、`gkdha`）时，
末尾的"辅音+元音"应该既能作为完整音节（如 `da`=大、`sha`=杀），也能**把元音独立成字**
（如 `ha`=好啊、`ho`=好哦、`na`=哪啊）。

libime 对单独输入的 `ha` 能给出"好啊"（`ha`→好啊），但在长简拼末尾（如 `jrmsha`）会把 `ha`
合并成"哈/杀"（`jrmsha`→进入秒杀），因为整体 LM 概率倾向合并音节。

## 解决方案：通用元音尾词组合 boost

### 1. 元音尾词预设（abbr_presets.h）

在预设表新增一批"辅音+元音"的元音尾词（元音独立成字）：
- `ha → 好啊`、`ho → 好哦`、`he → 好呃`、`hi → 嗨`
- `na → 哪啊`、`no → 哪哦`、`ya → 呀`、`wa → 哇`、`wo → 我哦`、`nia → 你啊`

这些词本身 libime 能出（ha→好啊），但作为长简拼末尾时会被合并。把它们作为"尾词"，
与前面的简拼词组合。

### 2. 通用组合算法（vowel_tail_combined / vowel_tail_boost）

新增 `vowel_tail_combined(input)`：
1. 当输入长度 ≥ 4，尝试从末尾匹配"元音尾词"（优先最长，如 `nia`=3，其次 `ha`=2）。
2. 把输入拆成 `前缀 + 尾词`（如 `jrmsha` → `jrms` + `ha`）。
3. 前缀用 `lookup_pinyin_boost` 查（如 `jrms`→家人们、`xdm`→兄弟们、`gkd`→搞快点、`zg`→中国）。
4. 尾词也用 `lookup_pinyin_boost` 查（如 `ha`→好啊、`ho`→好哦）。
5. 组合返回 `前缀词 + 尾词`（如 家人们 + 好啊 = **家人们好啊**）。

新增 `vowel_tail_boost(input, cands)`（CLI 用）：若 `vowel_tail_combined` 返回非空且候选列表
中无此组合，则插入候选首位。

### 3. CLI 接入

`boost_abbreviation` 末尾（`suffix_boost` / `prefix_boost` 之后）调用 `vowel_tail_boost`。

### 4. addon 接入

`updateUI` 的 boost 逻辑中，当完整匹配未命中（`pword` 为空）、`boostInsertWord_` 也为空时，
调用 `vowel_tail_combined(compact)`，若返回非空则设为 `boostInsertWord_`（插入候选首位）。

## 说明

- 这是**通用机制**：只要前缀在 boost 表（或用户自定义 abbr）中有词、且尾词是元音尾词，
  就能组合出"XX好啊/XX好哦/XX哪啊/XX呀"等。
- 用户自定义简拼（`~/.config/pinyin-ime/abbr.txt`）同样参与 `lookup_pinyin_boost`，因此
  自定义前缀也能与元音尾词组合。
- 前缀不限于 boost 词：libime 若能自然解码（如 `wmho`→我们好哦），则无需 boost。
- 尾词表可继续扩充（如 `ma`→吗、`ba`→吧 等），但需注意这些词本身是完整拼音（吗/吧），
  元音独立的意义较弱，暂不加入。
