# 便携运行时包 + 端到端安装验证（v0.9.189）

> 2026-11-26 18:45 · 豆包 · 版本 0.9.188 → 0.9.189

## 1. 背景

v0.9.187/188 解决的是「包里有什么、怎么核对」。但实际部署里还有一类场景装不了 rpm/deb：只读 rootfs 的容器、云桌面、外挂 `/usr` 的沙箱。旧 `build_release.sh` 就是为这类场景写的，但它绑死 `/workspace`、`$DEPLOY/opt`、`pinyin-ime-s3` 和 aarch64，换机器就废。

## 2. 改动

1. `scripts/build_packages.sh` 新增 **`runtime` 模式**（`all` 默认包含）：
   - 复用同一棵 `stage_rootfs`，产出 `dist/pinyin-ime-runtime-<ver>-<arch>.tar.gz`；
   - 包内是完整 `usr/` 安装树 + `install.sh`（`tar cf - usr | tar xf - -C /`，需 root，装完 `fcitx5 -r`）；
   - `BUILD-INFO.txt` 记录 version/arch/构建时间/addon 目录/数据位置。
2. `write_checksums()` 同步支持 runtime，`all` 模式清单变三条。
3. `scripts/build_release.sh` 标注为**历史脚本**：头部写明依赖旧沙箱布局、生产打包改用 `build_packages.sh`，保留仅供追溯。
4. `ci_static.sh` 增 2 条守卫：`build_packages` 必须支持 `build_runtime`、`build_release` 必须含「历史脚本」提示。

## 3. 验证（chroot x86_64）

打包（`build_packages.sh all`）：

| 产物 | 大小 |
| --- | --- |
| `pinyin-ime-0.9.189-1.x86_64.rpm` | 22,744,028 B |
| `pinyin-ime_0.9.189_amd64.deb` | 22,734,452 B |
| `pinyin-ime-runtime-0.9.189-x86_64.tar.gz` | 22,729,844 B |

`sha256sum -c SHA256SUMS_v0.9.189`：**三项全部 OK**（清单里没有 0.9.186/187/188 的旧包）。

**端到端安装测试（不是只看包结构）**：

1. runtime 包解压 → `sh install.sh` → `/usr/bin/pinyin_ime_cli`、`/usr/lib/x86_64-linux-gnu/fcitx5/libpinyinime.so`、`/usr/share/libime/zh_CN.lm` 全部就位，`pinyinime.conf` 的 `Version=0.9.189`、`Library=libpinyinime`。
2. **不传任何 `--lm` / `--dict`**，直接 `pinyin_ime_cli --batch`：`nihao→你好`、`woaibeijing→我爱北京` —— 默认搜索路径（含 `/usr/share/libime/...`）有效。
3. `dpkg -i --ignore-depends=fcitx5,libime pinyin-ime_0.9.189_amd64.deb` → `Status: install ok installed`、`Version: 0.9.189`、`pinyin_ime_cli 0.9.189`。

## 4. 安装测试暴露的问题（重要）

`dpkg -i` 报了：

```
dpkg: warning: trying to overwrite '/usr/share/libime/sc.dict',
 which is also in package libime-data 1.1.5-1
```

也就是说**包内自带 `sc.dict` 会与发行版的 `libime-data` 撞文件**，正常安装会被 dpkg 拒绝（测试里靠 `--force-overwrite` 才装上）。两个选项：

1. **自包含**（现状）：包内带 LM+词典，`Depends` 不写 `libime-data`，但必须声明 `Conflicts/Replaces: libime-data`，否则升级/卸载会互相踩。
2. **依赖发行版数据**：去掉包内 LM/sc.dict，`Depends: libime, libime-data`，包体积从 22.7MB 降到 ~1.4MB；缺点是数据版本随发行版浮动，准确率不可控。

这个取舍需要拍板：我倾向 **2（依赖 libime-data）**，理由是本项目的评测基线绑定「libime 1.1.5 的 zh_CN.lm + sc.dict」，跟着系统走反而与真实用户环境一致；但若要做「开箱即用、数据版本固定」的发行版，则选 1 并补 `Conflicts/Replaces`。
