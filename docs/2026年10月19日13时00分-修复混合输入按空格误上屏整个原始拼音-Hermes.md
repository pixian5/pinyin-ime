# 2026年10月19日13时00分-修复混合输入按空格误上屏整个原始拼音-Hermes

## 问题现象

用户反馈（更精确）：**"首位既显示文字又显示这个字的全拼，仍然把整个用户原始输入直接上屏；用户进行选词的时候，例如用户输入了六个字，前三个字用户选出来了词，第4个字敲空格选首位，但是把整个用户原始输入直接上屏"**。

复现用例：
- 输入 `woshizg`（我是中国，全拼+简拼混合）→ 按空格上屏 **`woshizg`**（整个原始输入），而不是"我是中国"
- 输入 `nihaozg`（你好中国）→ 按空格上屏 **`nihaozg`**，而不是"你好中国"

## 根因

`keyEvent` 空格处理的**中英自动混输判断**：

```cpp
if (!compactRaw.empty() &&
    !is_valid_pinyin(compactRaw) &&
    (ctx.candidates().empty() || compactRaw.size() > 4)) {
    state->commitText(state->rawInput_);   // 把整个原始输入上屏！
    ...
}
```

对含简拼的混合输入（`woshizg`、`nihaozg`）：
- `compactRaw = "woshizg"`（去隔音/空格）
- `is_valid_pinyin("woshizg")` → DP 切分失败（`zg` 不是合法音节，`wo`+`shi`+`z`+`g` 无法完全切分）→ **false**
- `compactRaw.size() = 8 > 4` → 条件成立
- → 把 `rawInput_`（`woshizg`）整个上屏

但 libime **实际能给出中文候选**（"我是中国/你好中国"）。用户想打中文，却因 `is_valid_pinyin` 判不了 `zg` 简拼段而被当作英文上屏。

## 修复

**核心原则：只要当前有中文候选，就优先选候选，绝不把原始输入当英文上屏。**

修改 `pinyinime.cpp` 混输条件：

```cpp
if (englishDoubled ||
    (!compactRaw.empty() &&
     ctx.candidates().empty() &&          // 关键：仅当无候选
     !is_valid_pinyin(compactRaw))) {
    state->commitText(state->rawInput_);
    ...
}
```

- `englishDoubled`（含双写辅音 ll/oo 等）→ 明确英文，上屏英文
- 否则**仅当 `ctx.candidates()` 为空**（确实无中文候选）且非合法拼音才上屏英文
- 只要候选非空 → 走 `selectCandidate` 选候选

CLI 交互态（`pinyin_ime_cli.cpp` ~2371 行）同步修复：混输判断加 `candsNow.empty()` 条件。

## 关键经验

- `is_valid_pinyin` 只能判断"纯全拼"，对**含简拼的混合输入**（如 `woshizg`）会误判为英文，但它其实是合法中文输入。
- 判断是否英文不能只看拼音合法性，还要看**是否有中文候选**。libime 对混合输入也能给出候选。
- 只要 `candidates()` 非空，就应优先选候选；仅当无候选时才把输入当英文上屏。
- 修复要同时覆盖 addon（`pinyinime.cpp`）和 CLI（`pinyin_ime_cli.cpp`）的交互态 + 批处理模式。
