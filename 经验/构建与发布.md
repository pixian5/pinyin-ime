# 构建与发布经验

- **libime 数据分两套路径**：`/usr/share/libime/{zh_CN.lm,sc.dict}` 是 addon/系统输入法常用数据；CLI 显式传 `/usr/lib/x86_64-linux-gnu/libime/zh_CN.lm` 时两者内容可能相同，但评测前仍要用 `md5sum`/`ls -l` 确认，别假设。
- **deb 依赖不是装饰**：`Depends: libime` 在 Ubuntu 24.04 不存在，`dpkg -i` 会直接失败；正确依赖是 `fcitx5, libimecore0, libimepinyin0, libime-data`。`test_install.sh` 的 `--ignore-depends` 不能替代普通安装验收。
- **发布链已分四段**：`build-eval`（编译+721 单测+CLI 快照+fuzz+holdout 基线）、`package`（deb/rpm/runtime+SHA256）、`install-matrix`（30 项安装/卸载）、`addon-acceptance`（装 deb 后 8 句真实按键）。push 触发，别把 1200 句全量评测塞进每次 push。
- **包体积与数据归属**：v0.9.190 起 deb/rpm 依赖 `libime-data`，runtime 才自包含 `sc.dict`；runtime 卸载清单若漏 `usr` 会误删 `sc.dict`，已修。
- **版本单一来源**：`VERSION` 是唯一版本来源，`fcitx5-addon/pinyinime.conf`、包名、CI 产物都跟它走；改代码必须同步升版并发包。
- **大文件与历史**：仓库曾用 `git filter-repo` 清 220MB 历史二进制；不要把 build 产物、`.so`、rpm/tar.gz 提交回仓库。
- **CI 页面**：GitCode/AtomGit 没有 Actions 页，只有 GitHub 的 `.github/workflows/ci.yml` 会执行；GitCode 仅作备份远端。
