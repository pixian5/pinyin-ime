# 评测与基线经验

- **先问“是哪条路径”再比数字**：CLI `--batch` 是整串拼音一次解码；CLI 交互和 fcitx5 addon 是每键刷新。同一句长 baike，两者首选可以完全不同（“文献多见” vs “文戏安多”）。addon 28.00/80.31 和 CLI batch 30.00/86.04 不是同一口径，不能直接相减。
- **batch 数字只当回归基线/上限**：它证明模型和候选池能力，不代表用户真实输入。真实用户基线要用逐键输入或 addon 上屏。
- **addon 全量评测会带用户学习**：addon 每提交一句会更新 user.history/user.dict；批量评测要用独立 HOME/用户目录，避免上一句的错误自我强化。CLI batch 默认不学习。
- **长句提交是异步的**：空格后 Entry 可能短暂为空；必须轮询到非空或超时，否则会把空串/上一句迟到提交算进下一句。每句前 CLEAR，窗口 focus 后等 0.8s。
- **延迟别拿墙钟当引擎耗时**：addon 评测的 P50 包含 xdotool 每键 5ms、settle、提交轮询；短句 500ms 主要不是 addon 卡。要拆 `type_ms` / `commit_ms`。
- **addon 评测暴露出产品 bug 时，先复现单句再跑全量**：v0.9.202 的 28/80 看似模型差距，实际是逐键消歧把 `xian` 拆成 `xi'an`；单句 60.61% 与 CLI batch 78.12% 的对比比全量均值更快定位。
- **Top-k 必须先有召回上限**：只看 top1 会把“候选里有正确答案但排得深”误判成模型不行；至少同时看 Top10/MRR/命中后按键和翻页率。
- **评测语料仍可能泄漏**：v0.9.197 的 42.67% 是训练集泄漏复现值；clean 重训后 30.00/86.04 才是可用基线。改语料/模型后先跑泄漏检查，再看准确率。
- **候选池转储必须按显示顺序，不是 libime 原始顺序**：`displayToRaw_`、`boostSwap_`、`boostInsertWord_`、云候选都会改变空格实际选中的候选；按原始列表算 Top1 会和 `sent_acc` 不一致（v0.9.204 4 句里 2 句不一致）。
- **Top1 与 Top5 的差值就是重排空间**：addon 1200 句 Top1 30.25%、Top5 45.17%、Top10 49.83%；Top5 比 Top1 高 14.92pp，先做重排比扩召回更划算。
- **提交前补消歧不一定有收益**：`xianyoud` 这类歧义缩写即使完整输入再消歧，仍可能被上下文规则拆成“西安有点”；全量无提升且 P95 变差，应撤销并用专用 boost/词表处理。
- **简单权重扫描先做 CLI，不要反复重编 addon**：v0.9.204 扫 alpha 0.25/0.5/1.0/1.5，Top1 依次 30.33/29.42/26.67/25.33，确认 0.25 最优；词数/长度线性特征只 +0.09pp，不值得落地。
- **4-gram 换位要加原分差门限**：无条件让字符模型重排会把高置信 top1 换掉；只允许 `base >= baseTop - 1.0` 的候选参与，addon 1200 句 30.17%→30.92%，但 Top5 会下降，需按产品目标取舍。
- **4-gram 收益要分长度看**：1200 句离线扫描中，短候选（<18 字节，约 6 个汉字）改回 trigram 与全量 4-gram 的 Top1 同为 31.58%，但 42 例快照里 `年轻→年青`、`加入什么→进入睡眠` 两处回归被消除；短文本保留 trigram 是零成本护栏。
- **4-gram 低频条目可以大幅剪枝**：count>=2 时 1200 句候选池 Top1 与全量 4-gram 同为 31.58%，但上下文 19.7 万→1.07 万、模型 6.6MB→3.17MB；先剪枝再谈模型体积成本。
- **换模型格式先保 v1 兼容**：v2 加载器必须允许 version=1/2，v1 文件没有 4-gram 段就回退原插值；否则旧包/旧用户模型会直接加载失败。
- **1200 句全量评测不要塞进 push CI**：addon 真实上屏跑一次约 15 分钟，push 每次跑会拖慢反馈；用 `schedule`/`workflow_dispatch` 独立 job，复用 package 产物，报告上传 artifact。
- **CI 里 GTK harness 首行可能比本地慢一个数量级**：本地 chroot 1s 内出 READY，GitHub runner 5s 超时；首行等待至少 20s，后续行再用短超时，否则会把启动慢误判成 addon 不工作。

## 训练集泄漏会造出 15pp 的假突破（2026-11-27）

- 现象：把 `bench/corpus` 原始 16k 句（未跑 `clean_corpus.py`）直接训练字符 4-gram，CLI/addon 从 31.67% 跳到 47.08%。
- 原因：原始 `bench/corpus` 含 eval-only 文件与 holdout 的 exact/近重复句子；clean 12,130 句版本只有 31.0%（372/1200）。
- 纪律：所有字符/词 LM 实验必须从 `bench/clean_corpus.py --near-dup-threshold 2` 产物训练，并用 `check_train_leakage.py` 检查；不要用 holdout 调阈值后再在同一 holdout 报告收益。
- 识别信号：指标突然接近 recall@45（53.58%）且各域同步大涨，先查训练语料是否混入评测集。

## Top1 与 Top5 要一起看

v0.9.209 的 `-100` 硬门限把 Top1 提到 30.92%，但 addon Top5 从 45.92% 掉到 45.17%。v0.9.210 改成 `-1` 软降权后 Top1 持平、Top5 46.17%，说明门限惩罚值本身就是 Top1/Top5 的平衡旋钮，不能只盯 Top1。
