# 评测与基线经验

- **先问“是哪条路径”再比数字**：CLI `--batch` 是整串拼音一次解码；CLI 交互和 fcitx5 addon 是每键刷新。同一句长 baike，两者首选可以完全不同（“文献多见” vs “文戏安多”）。addon 28.00/80.31 和 CLI batch 30.00/86.04 不是同一口径，不能直接相减。
- **batch 数字只当回归基线/上限**：它证明模型和候选池能力，不代表用户真实输入。真实用户基线要用逐键输入或 addon 上屏。
- **addon 全量评测会带用户学习**：addon 每提交一句会更新 user.history/user.dict；批量评测要用独立 HOME/用户目录，避免上一句的错误自我强化。CLI batch 默认不学习。
- **长句提交是异步的**：空格后 Entry 可能短暂为空；必须轮询到非空或超时，否则会把空串/上一句迟到提交算进下一句。每句前 CLEAR，窗口 focus 后等 0.8s。
- **延迟别拿墙钟当引擎耗时**：addon 评测的 P50 包含 xdotool 每键 5ms、settle、提交轮询；短句 500ms 主要不是 addon 卡。要拆 `type_ms` / `commit_ms`。
- **addon 评测暴露出产品 bug 时，先复现单句再跑全量**：v0.9.202 的 28/80 看似模型差距，实际是逐键消歧把 `xian` 拆成 `xi'an`；单句 60.61% 与 CLI batch 78.12% 的对比比全量均值更快定位。
- **Top-k 必须先有召回上限**：只看 top1 会把“候选里有正确答案但排得深”误判成模型不行；至少同时看 Top10/MRR/命中后按键和翻页率。
- **评测语料仍可能泄漏**：v0.9.197 的 42.67% 是训练集泄漏复现值；clean 重训后 30.00/86.04 才是可用基线。改语料/模型后先跑泄漏检查，再看准确率。
